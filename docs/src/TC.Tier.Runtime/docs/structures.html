    Structures 使用指南——Ring / 索引 / Log / Metadata / Mirror / Snapshot

    给谁看：用结构层组合存储模型的人（KV / WAL / 队列 / 时序形态的构建者）。 回答什么：七种结构各自是什么、怎么选、怎么组合成 KV、恢复与生命周期怎么走、什么绝对不要做。 本篇只讲怎么用——机制细节（帧格式、水位全表、协议内部状态机）在文末"想深入"链接与源码注释， 不在此重复。每结构自有引擎（StorageEngine），文件系统 = 构造传哪个 IFileSystem；meta 统一协议见 meta.md；性能数字见 perf/structures-perf-baseline.md。

    0. 快速上手：组合 KV（三步，可运行）

    0.1 声明封闭形态（[RingKey] 源生成器，一行）

    开放泛型（BlittableRing<TKey>/HashIndex<TKey> 等）的构造是 protected internal——消费面只经 [RingKey] 生成的封闭薄类（编译期封闭 + Create 工厂）。内置 long 已声明（TC.Tier.Runtime 程序集），RingOfLong/HashOfLong/BTreeOfLong/SkipListOfLong 开箱即用；自定义 Key 在消费程序集 加一行：

    [assembly: RingKey(typeof(OrderId))]   // 产出 RingOfOrderId / HashOfOrderId / ...

    0.2 装配与写读（真实签名）

    using TC.Tier.Core.IO;
using TC.Tier.Runtime.Storage;
using TC.Tier.Runtime.Structures.Ring;
using TC.Tier.Runtime.Structures.ProbingIndex;
using TC.Tier.Contracts.Structures;

// ① 文件系统 + 配置（默认值即生产值；示例用小型页池便于观察）
using var fs = TierFs.New("memory:");
var ringSettings = new BlittableRingSettings(new StorageEngineOptions("kv-ring", 64L << 20))
{
    PageSize = 4096, MemorySize = 64 * 1024, MutableFraction = 0.5,
};
var hashSettings = new HashIndexSettings(new StorageEngineOptions("kv-hash", 64L << 20));

// ② 封闭类型 Create 一步就绪（Create = 构造 + Initialize + WaitForReady）
using var ring  = RingOfLong.Create(ringSettings, fs);        // 真相源：record 流
using var index = HashOfLong.Create(fs, hashSettings, ring);  // 派生数据：判等闭环必注入 ring

// ③ 写读编排（正序两步写 / 两段合口径读）
static LogicalAddress KvPut(RingOfLong ring, IIndex<long> index, long key, ReadOnlySpan<byte> value)
{
    var addr = ring.Write(key, value);        // ① 真相源先写，得地址
    index.Insert(key, addr, LogicalAddress.Empty);   // ② 索引后插（指向该地址）
    return addr;
}

static bool KvTryGet(RingOfLong ring, IIndex<long> index, long key, Span<byte> buf, out int len)
{
    len = 0;
    var addr = index.Find(key);               // ① 索引命中得地址
    if (addr == LogicalAddress.Empty) return false;
    len = ring.GetValue(addr, buf);           // ② 真相源按址取值
    return true;
}

    终态读形态（批量最快）：ring.EnterReadScope() + index.EnterScope() 一批一进出 + IndexScope.Find + Ring.GetValueSpan（零拷贝切片；溢出 record 回退 thread-static 拷贝）。 批口径实测反超 FASTER（perf 文档 §3）。

    0.3 恢复（两段式协议，锚点 W）

    ① Ring.Create → 恢复水位；锚点 W = ring.ReadOpaqueMeta()
   （无锚点 / 损坏 / W 越过当前尾 → 回退 BeginAddress——宁可旧多重放）
② index 拉流重放：ScanAsync(W, TailAddress) 逐条 Insert 自建
   （Hash/SortedIndex 有主存储帧时优先载帧，见 §3.2）

    锚点 W = 索引上次主存储 dump/重放完成的水位，经 Ring 的 opaque 随水位线原子落盘；每次 dump/重放后 ring.SetOpaqueMeta(W) 即可。恢复协议全文见 meta.md。

    1. 概念（术语在此定义）

    • 2 主结构 + 4 搭配件 = 产品发生器：Ring（数据真相源）/ Log（操作流）是主结构； 索引/元数据/镜像/快照是搭配件（经桥单向依赖、可摘——存在性=优化非正确性）。
    • 真相源 vs 派生数据：Ring 是数据真相（record 流），索引是派生数据（可重建）。 写编排正序：先真相源写、再索引插；反向 = 索引指向不存在的数据。
    • 地址一等公民：16B LogicalAddress 是唯一的取值句柄——先经索引发现地址，之后永久直达取值 （跳过 hash）；判等/哈希只比较地址本身。
    • 恢复统一模型：载基线（快照/镜像，到 W）+ 重放（W, 尾]。快照按字节截断（纯流式）， 镜像按版本号截断（版本链 N=2/回跳/回退）——同族异坐标系。
    • 术语：WAL = 写前日志（Log 即 WAL）；RCU = 读-拷贝-更新（Ring 原地更新语义）； opaque = 外部记录随水位线原子落盘的扩展槽（meta.md §4）；2PC 六件套 = Prepare/ConfirmCommitted/ OnCommitted/Abort 的事务参与协议（§4）；帧 = 持久化格式的三段式单元（头先行校验/体/尾 CRC）。

    2. 怎么选（七种结构速查）

    结构 是什么 何时用 注意
    Ring（BlittableRing<TKey>） 追加式 KV 环：页池 + 单调逻辑地址 + 原地更新 + 环形驱逐 主真相源——KV 数据本体；高并发写/读 默认内存上限 16GB（MemorySize 旋钮）；TKey : unmanaged
    HashIndex 探测族：条目=地址+tag，不物化 key，判等经 KeyResolver 回读 点查为主、内存最省（实测 161 ns） 构造必注入 KeyResolver（判等闭环）；无有序遍历
    BTreeIndex / SkipListIndex 比较族：条目物化 (key, 地址)，有序遍历/range scan 需要排序/范围查询 单写者（插入）；恢复重放需要 KeyResolver
    Log（EntryLog/DeltaLog） WAL 页帧流：组提交 + 恢复水位 纯顺序日志；checkpoint delta 单写者；超单页抛（entry 不跨页）
    Metadata（VersionedMetadata） 版本链追加式单值元数据，N=2 轮转回收 跨重启单值状态（水位/配置/锚点）；meta 外部隔离传输 PayloadSize 须 ≥ 托管块上界
    Mirror（WholeMirror/PagedMirror） 字节镜像：完整状态基线的版本链形态 整体快照外存（流式）/ 分页增量镜像 与 Snapshot 同族异坐标系
    Snapshot（StreamSnapshot） 完整状态基线的纯流式形态（按字节截断） 流式帧文件快照 无版本概念

    索引三选：点查 → Hash；有序遍历/range → BTree/SkipList；高写并发小记录 → SkipList（无分裂重排）。 性能对照见 perf/structures-perf-baseline.md §3。

    3. 怎么用（关键用法）

    3.1 Ring：写读 / 水位 / 线程模型

    • 写：Write/WriteAsync（追加返回地址，多线程并发安全）；UpdateValue（原地 RCU 覆写，同尺寸）； 批量写经 BeginWriteBatch（多写者无锁窗口）。
    • 读：GetValue（拷贝出参，自保护）；GetValueSpan（零拷贝切片——必须在 ReadScope 内消费， 驱逐经 epoch 排水，scope 外持有 = 使用已回收内存）。
    • 水位（只记三个就够）：BeginAddress（头）/ TailAddress（分配尾）/ FlushedUntilAddress（已落盘水位 W）。其余只读视图（Safe* 系列 = 排水完成可安全消费版本）见类型 XML 注释。
    • 截断：TruncatePrefix（头回收，与写完全并行）；TruncateSuffix（尾回退，D2 唯一异常路径）。
    • 快照：OpenSnapshotReader/Writer 区间字节流导出/导入。

    3.2 索引：契约与持久化

    public interface IIndex<in TKey>   // 五成员最小协议（组合层消费面）
{
    LogicalAddress Find(TKey key);                 // Empty = 不存在
    LogicalAddress Insert(TKey key, LogicalAddress valueAddress, LogicalAddress beginAddress);
    bool Delete(TKey key);
    long EntryCount { get; }
    long IndexSize { get; }                        // 索引内存占用（字节）
}

    两族基类均实现 IIndex<TKey> + ITransactionParticipant，均提供 BeginAddress（恢复窗口起点）、 EnterScope() → IndexScope（跳 epoch 的点查形态）、FindBatch(keys, results)（批量）。

    持久化两形态（恢复加速，非正确性——不配也安全，走全量重放）：

    • HashIndex：自建主存储（内置后台 dump，PersistenceKind 可关）；
    • SortedIndex：桥接注入 ITransferPersistence（内置桥 WholeMirrorPersistence 托管 WholeMirror； 不注入 = 纯重放 fail-safe）。

    3.3 Log：组提交与回放

    Append（返回地址，超单页抛）→ 批量 BeginAppendBatch() → 显式提交 CommitAsync（= flush + 推进 CommittedOffset + meta.Commit）或 Flush（只落盘不推进水位）。回放 Replay（只读已提交， verifyCrc 可选）。组提交策略（字节量/条数/时间间隔三维）构造注入。单写者——多生产者经队列汇聚。

    3.4 Metadata / Mirror / Snapshot

    • Metadata：Write(data)→地址 / Read(dst) / AsSpan() / GetRef<T>()；崩溃安全天然（写到一半 = 旧版本完好）。两消费形态：直接用（跨重启单值状态）；3a 外部隔离传输（MetadataMetaTransport 托管， 勿自写单槽文件）。
    • Mirror：写会话三拍 BeginSession() → AppendChunk(bytes)×n → EndSession()（不知尺寸、零缓冲， EndSession flush）；ReadChunk 按帧读。PagedMirror 逐页 WritePage。2PC 六件套全实现（Abort = 丢弃 未确认会话）。
    • Snapshot：OpenWrite/OpenWriteRange → StreamFrameWriter（Write + Complete）；OpenRead 反向。 ⚠️ 与 Ring 自带的区间快照（§3.1）无引用关系——那是 Ring 导出能力，这是独立文件形态。

    3.5 生命周期与 2PC

    • 生命周期（全部结构统一）：Create(...) 一步就绪（= 构造 + Initialize + WaitForReady）； 或构造 → Initialize(hints) → WaitForReady 分步（观察恢复/注入恢复窗口）。Dispose 幂等。
    • 跨结构原子性：2PC 六件套由 ITransactionParticipant 暴露，协调器 = Transactions/TransactionLog （写独立 commit record 文件驱动 Prepare/Confirm/Abort）。上层编排归 Session（统一协调协议层： 写=staged 物化委托经单飞提交管线、检查点=管线串行回合、悬挂裁决）——使用指南见 session.md。

    4. 反模式（组合层必守）

    1. 写编排反序：先 index.Insert 再 ring.Write——索引指向不存在的数据。
    2. 零拷贝 span 逃逸 scope：GetValueSpan 返回值禁止越过 ReadScope.Dispose()。
    3. Log 并发 Append：单写者硬性要求（多生产者经队列汇聚）。
    4. 绕过 [RingKey] 直接继承开放泛型——封闭薄类是唯一消费面（分析器诊断不满足 unmanaged 约束的声明）。
    5. 为索引手搭 checkpoint 引擎/存储——HashIndex 走自建主存储（内置）；SortedIndex 走 ITransferPersistence 注入。主存储/dump 机制见源码注释与设计稿。
    6. 给地址直达读加会话/索引——地址即句柄：GetValue(addr) 永久零税。
    7. 跨实例组合 DeleteOnClose=true——跨重启组合必须 DeleteOnClose=false（否则索引重建时真相源被清）。
    8. 增长后检查索引阈值——增长必须在插入之前检查（增长时刻表内条目必可经 KeyResolver 解析）。
