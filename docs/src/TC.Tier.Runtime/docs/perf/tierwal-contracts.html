TierWAL 三份性能契约基线

实测于本机（12 逻辑核 / .NET 8.0.30 / Windows 11 / NTFS）：机械盘 = F: WD10EZEX，SSD = C: NVMe； 探针运行介质经 TMP/TEMP 重定向控制（磁盘口径 = 机械盘 F:，最坏介质）。日期：2026-08-26。 判定口径（设计稿 §3）：① 元数据槽原子写 p99 <10ms 级、抖动不触发选举失败（p99.9 <150ms 窗口下界）； ② 磁盘随机起点重放吞吐（RTO 外推）；③ 快照导出+导入+增量重放收敛时间。

契约① 选举窗口 ↔ 元数据持久化（--wal-meta-probe）

  • 形态：128B term/vote 元数据，WriteMetaAsync = stage + 一次提交 = 应答持久化；1000 迭代。
  • 运行： 
    dotnet run --project benchmarks/TC.Tier.Products.Benchmarks -- --wal-meta-probe virtual 1000 all        # 基线
dotnet run --project benchmarks/TC.Tier.Products.Benchmarks -- --wal-meta-probe virtual 1000 all true   # 载体写穿档（第 4 参）
IO 模式 基线 p50 基线 p99.9 写穿档 p50 写穿档 p99.9 判定
buffered 20.2ms 163.9ms 0.198ms 1.08ms 写穿档达标
WriteThrough 30.6ms 232.4ms 0.179ms 1.74ms 写穿档达标
DIO 16.7ms 125.1ms 0.176ms 1.06ms 写穿档达标
DIO+WriteThrough 30.9ms 233.4ms 0.169ms 0.58ms 写穿档达标
  • 现状选型：virtual 介质 + raft 语义持久化 → 挂载 CarrierWriteThrough=true（载体句柄级写穿， journal 提交免独立 fsync——写穿完成即单屏障）；基线四格 p99.9 全 ≥150ms 不达标。

契约② 重放吞吐 ↔ RTO（--wal-replay-probe）

  • 形态：50 万条 × 64B 组提交写入 → 从 count/2 随机起点全量重放（段表二分 + 段内扫帧）。
  • 运行：dotnet run --project benchmarks/TC.Tier.Products.Benchmarks -- --wal-replay-probe <virtual|local> 500000 64
介质 写入（组提交） 重放吞吐 RTO 外推（100 万条）
virtual 328K 条/s 2.67M 条/s / 163.2MB/s 0.37s
local — 2.54M 条/s / 155.2MB/s 0.39s

契约③ 冷节点追赶 ↔ 收敛（--wal-catchup-probe）

  • 形态（镜像快照接线后——快照 = 主数据镜像帧流 + 注入传输面）：20 万条主节点 → 一体快照（N₀=20 万， 镜像 12.97MB）→ 导出（经注入传输面）→ 增量 2 万条 → 冷节点导入 → 从 N₀+1 增量重放。
  • 运行：dotnet run --project benchmarks/TC.Tier.Products.Benchmarks -- --wal-catchup-probe <local|virtual> 200000 20000 64
介质 快照导出 导入 增量重放 收敛合计
local 0.10s（124.5MB/s，192 万条/s） 0.052s 0.01s（1.92M 条/s） 0.17s
virtual 0.11s（115.9MB/s，179 万条/s） 0.057s 0.01s（1.76M 条/s） 0.18s
  • 判定：镜像快照（第三部件）与旧形态（主数据 [Head..N₀] 导出）同量级——快照生成+导出+安装+重放 全链收敛 <0.2s，冷节点追赶不构成 RTO 瓶颈。

快照存储选型（--wal-snapshot-store-probe，镜像快照设计稿 §3.4）

  • 形态：方案 A（段增量——每次只写增量段）vs 方案 B（全量重写——每次重写整个镜像）；条目流 64B/条。
  • 运行：dotnet run --project benchmarks/TC.Tier.Products.Benchmarks -- --wal-snapshot-store-probe <local|virtual> <imageMb> <snapshots> 64
场景 A 写 B 写 A 读（拼接） B 读（单段）
256MB × 4 快照（local） 256MB / 0.36s 640MB / 0.92s（2.6× 字节差） 2404MB/s 2062MB/s
256MB × 8 快照（local） 256MB / 0.31s 1152MB / 1.74s（4.5× 字节差） 2853MB/s 2332MB/s
  • 结论（数字定案）：方案 A 胜——写侧 = 镜像总量（恒增量）vs 累计全量（Σk×delta），快照越频繁省得越多； 读侧持平（拼接开销可忽略）；A 的段累积合并成本 = B 单次全量写（低频触发，raft 只需最新快照）。 → 落地面 = IncrementalSnapshot（段 = 帧 + 段表 meta O(1) 恢复 + 阈值合并）。

稳定性矩阵（--wal-append-probe，F: 机械盘 local；第 5 参 = 载体写穿档——IS-03，virtual 专属）

介质 提交形态 p50 p99/p50 抖动 吞吐
virtual（句柄级） 组提交（批 100） 0.054ms 2.2× 200K 条/s
virtual（载体写穿档） 组提交（批 100） 0.054ms 2.2× 239K 条/s
local 组提交（批 100） 0.053ms 2.4× 362K 条/s
virtual（句柄级） 单条（每写 fsync） 33.4ms 3.3× 28 条/s
virtual（载体写穿档） 单条（每写 fsync） 0.792ms 2.5× 984 条/s
local buffered 单条（每写 fsync） 41.6ms 2.6× 25 条/s
local WriteThrough 单条（每写 fsync） 0.519ms 2.3× 1702 条/s
  • ★ virtual 完整能力 = 挂载级载体写穿档（--wal-append-probe virtual 1000 5000 none true）—— 单条提交 33.4ms → 0.79ms（42×）——与 local WriteThrough（0.52ms）同量级（免 fsync 生效）； 句柄级形态（无第 5 参）= RM-07 逐写 journal 提交（每写仍付 fsync——非功能缺失）。
  • 组提交（raft 主路径）p50 全介质全形态有界（0.05ms——内存快路径）；吞吐 virtual 写穿档 239K vs local 362K（journal 记录成本残余——非 fsync）；单条提交 = IO 模式/写穿档主导变量。
  • 复现说明：机械盘单条提交 33-42ms 为 fsync 物理地板（非缺陷）；组提交形态下 p99.9 偶发单次峰 （~318ms，页 flush 提交刺），探针报告化时已加预热复核。
