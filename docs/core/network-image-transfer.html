镜像网络传输使用指南（NetworkImageTransfer——根空间 TCP 流式收发）

给谁看：需要把文件系统根空间经 TCP 推送到对端落盘的组件开发者（备份上远端、节点间镜像、 数据搬迁工具）。 回答什么：收发两端怎么写、TIN1 协议怎么保证一致、边界与失败语义是什么。 定位：Core IO 镜像能力（RootSpaceImage 采集/还原，见 io.md §5.2）的 网络发射端——载荷就是 TCA1 结构化流；对端不落盘而回传字节流的形态直接用 RootSpaceImage。

0. 一句话总纲

发送端 Send 把源根空间采集为 TCA1 流直写 TCP；接收端 ReceiveTo 还原到空根空间并回传回执—— 两端各自拿到 NetworkTransferResult，Verified=true = 对端落盘与本地逐帧一致（端到端确认）。

1. 快速上手

using TC.Tier.Core.IO;
using TC.Tier.Core.IO.Net;

// ── 接收端（先起——监听绑定同步完成，起好再通知发送方，无绑定竞速）──
var recvTask = Task.Run(() =>
    NetworkImageTransfer.ReceiveTo(targetFs, port: 9100, ct: ct));
// 端口固定场景可先探测 listener 就绪；动态端口用 §2 预绑定形态拿 LocalEndPoint

// ── 发送端（采集本地根空间推送，阻塞至对端回执对账一致才返回）──
NetworkTransferResult sent = NetworkImageTransfer.Send(sourceFs, "10.0.0.8", 9100);
Console.WriteLine($"verified={sent.Verified} entries={sent.EntryCount} bytes={sent.RawBytes}");

// ── 接收端拿到自己的视角（Verified=true = 本地逐帧校验通过且回执已回传）──
NetworkTransferResult recv = recvTask.GetAwaiter().GetResult();
  • 两端都阻塞到收尾：发送端等到回执对账一致；接收端等到还原 + 本地校验完成。
  • 目标必须为空根空间（还原契约——非空抛 AlreadyExists，见 io.md §5.2）。

2. API 全表

成员 签名要点 说明
Send (IFileSystem source, string host, int port, ImageOptions? options = null, CancellationToken ct = default) 连接对端 → 握手 → 采集 TCA1 流直写 → 半关发送 → 等回执对账；不符抛 IOException
ReceiveTo（端口形态） (IFileSystem destination, int port, ImageOptions? options = null, CancellationToken ct = default) 自建监听（绑 loopback:port，绑定同步完成）；一次传送后即停
ReceiveTo（预绑定形态） (IFileSystem destination, TcpListener listener, ImageOptions? options = null, CancellationToken ct = default) 调用方自建并 Start() 的监听器——绑定先于发送方存在，结构性消除"接收端未就绪"竞速；监听器生命周期由本方法收口（结束即 Stop）
SendRaw（Raw 档） (IFileSystem source, string host, int port, CancellationToken ct = default) 整卷字节镜像（dd 档）：源须连续卷介质；源侧 EnterMaintenance(WriteOperations) = 传输窗口只读冻结；分帧推送 + 聚合 CRC 端到端对账
ReceiveRawTo（端口/预绑定形态） (IFileSystem destination, int port \| TcpListener listener, CancellationToken ct = default) 整卷字节镜像落盘：容量预检先于首字节写入（不足零受损）；逐帧 CRC + 长度对账；完成后 OnMirrorCompleted 重建内存元数据。整卷覆盖是破坏性操作（dd 语义）
TransferMode enum：Structural = 0 / Raw = 1 握手 mode 字节。Structural = TCA1 结构流；Raw = 连续卷整卷字节流（两档入口各自校验 mode，错档即拒）
NetworkTransferResult record(long EntryCount, long FrameCount, long RawBytes, bool Verified) 传送摘要；Verified 双端各自视角的一致结论（Raw 档 EntryCount 恒 0）

ImageOptions 与 RootSpaceImage 同一套（Compression None/ZLib/Zstd、QuietSource 静默源、 VerifyChecksums）——见 io.md §5.2（Raw 档不适用——字节镜像无压缩/过滤语义）。

3. 工作方式（TIN1 协议）

发送端                                接收端
  │ 握手帧 [magic][版本][mode] ──────→ │ 校验 magic/版本（错档即拒）
  │ TCA1 载荷（采集直写网络流） ──────→ │ 中转流适配（Restore 要求 seekable）
  │   逐帧 CRC                          │   还原 + 本地逐帧 CRC 校验
  │ 半关发送（Shutdown(Send)=EOF）───→ │ 尾对账（条目/字节/聚合 CRC）
  │ ←────────────── 回执帧（摘要+状态）── │
  │ 对账不符 → IOException              │ 回执已回传 → Verified=true

3.1 Raw 档载荷形态（mode=Raw）

发送端                                    接收端
  │ 握手 [TIN1][ver][mode=Raw] ──────────→ │ 连续卷介质校验（非连续卷 Unsupported）
  │ 声明帧 [源长 u64] ───────────────────→ │ 容量预检（不足写前拒绝——目标零字节受损）
  │ 数据帧 [len u32][payload][crc32 u32]─→ │ 逐帧 CRC 校验 → 顺序落盘（聚合 CRC 累计）
  │ 终结帧 [len=0] ──────────────────────→ │ 长度对账（实收==声明）→ OnMirrorCompleted
  │ 半关发送 ────────────────────────────→ │ 回执（CRC 字段=对端聚合载荷 CRC）
  │ 端到端对账（字节+聚合 CRC）→ Verified   │ Verified=true

  • dd 级语义：整卷原始字节顺序镜像，结构无关（WAL/快照/blob/配置全在 Fs 域全覆盖）； 源侧只读冻结 = EnterMaintenance(WriteOperations) 租约随传送进出。

  • 介质前提：双端均须连续卷（能力位 ContiguousCapture + IContiguousVolume，TierVolume 族）—— 结构化介质（Disk 目录树/Mem/Remote）不满足，走 Structural 档。

  • 两档入口错档即拒：ReceiveTo 只收 Structural、ReceiveRawTo 只收 Raw——模式由对端入口显式选择。

  • 双向对称：同一 TCP 连接，发起端既可 Send（采集推送）也可 ReceiveTo（接收落盘）——对端运行互补方法。

  • 端到端确认：TCA1 逐帧 CRC + 尾对账之上，接收端回执回传摘要——发送端确认对端落盘一致（不符抛异常）。

  • 半关发送：发送侧 Shutdown(Send) 产生 EOF 信号（对端 CopyTo 自然结束）；回执走接收方向仍通。

4. 边界与失败语义（v1）

边界 语义
阻塞式 API 同步方法——传送完成（或失败）才返回；长传送放专用线程，不要塞线程池热路径
单连接单传送 无续传、无多路复用——中断即作废（帧级断点续传为后续增强）
取消 ct 取消即中断发送——已发送部分不可恢复（接收端还原到一半的目标不保证可用）
接收绑定 端口形态绑 loopback——跨机接收用预绑定形态自选地址
目标非空 还原契约：非空抛 AlreadyExists——重传前先清目标
回执不符 发送端 IOException（传送不完整）；捕获后整体重传，勿续传半途状态

5. 反模式

  1. 先起发送方再赌接收端就绪——用预绑定 ReceiveTo(destination, listener) 形态：绑定先于 发送方存在，慢 runner 上"Sleep 赌绑定"必输。
  2. 拿 ReceiveTo 当常驻服务端口——一次传送后 listener 即 Stop；多轮传送每轮新建（或循环重建）。
  3. 取消后复用半途目标——取消/失败的目标根空间状态不可信，重传前清空或换新。
  4. 绕过回执判 Verified——Send 正常返回即已对账一致；不要自己再数对端条目二次校验。
