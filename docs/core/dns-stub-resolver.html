DNS Stub Resolver 使用指南（security-aware stub resolver——#498）

给谁看：需要 DNS 服务发现（K8s CoreDNS / Consul DNS 接口形态）的网关与服务组件开发者； 不引入任何第三方 DNS 包的消费方。 回答什么：怎么查 SRV/A/AAAA、TTL 缓存与负缓存语义、search/ndots 展开顺序、安全位（AD/CD/DO）怎么消费、边界与 Non-goal。

0. 一句话总纲

DnsStubResolver = 零外部依赖的 security-aware DNS stub resolver（RFC 1035/2782/6891 客户端面）： 查询 + 解析 + TTL 缓存 + EDNS0，AD/CD 位完整外显——DNS 的消费者契约到此为止。

1. 快速上手

using TC.Tier.Core.Net.NameResolution;

// SRV 服务发现（K8s headless / Consul DNS 主形态）
using var resolver = new DnsStubResolver();
var answer = await resolver.ResolveSrvAsync("_tcp.myapp.prod.svc.cluster.local");
foreach (var srv in answer.SrvRecords)
    Console.WriteLine($"{srv.Target}:{srv.Port} prio={srv.Priority} weight={srv.Weight}");

// A 地址查询（相对名走 search/ndots 展开）
var addrs = await resolver.ResolveAddressesAsync("myapp.prod.svc.cluster.local");
foreach (var ip in addrs.Addresses) Console.WriteLine(ip);
  • 服务器列表 / search 域 / ndots 缺省操作系统自举（Unix：resolv.conf；Windows：网卡 DNS 配置）—— K8s CoreDNS 形态零配置兼容；显式 DnsStubResolverOptions.Servers 永远优先。
  • 全异步、零线程创建；接收缓冲走池化（ArrayPool）低分配。

2. 行为契约

2.1 查询与解析

面 契约
记录类型 SRV（priority/weight/port/target）、A、AAAA；CNAME 跟随（深度上限 8，聚合 MinTtl）；SRV 不跟随（RFC 2782：属主不得为别名）
传输 UDP:53 首选 → TC 置位 TCP 重试（2 字节大端长度前缀）；单次收发超时 + 重试（指数退避），每次尝试轮换下一 server（ServFail/超时跟随）
TTL 缓存 进程内 LRU（容量有界）；键 = (类型, 名) 大小写不敏感；CNAME 链各跳分别缓存
负缓存 NXDOMAIN 与 NODATA（NoError 空记录）按 NegativeCacheTtl（缺省 30s）短窗缓存
应答码 NxDomain 以应答码外显（记录集空 + 负缓存 TTL），不抛异常；其余非 NoError 计失败跟随重试，耗尽抛 IOException
确定性 同应答字节 → 同结果（记录保持应答节顺序，零顺序扰动）

2.2 名字展开（search/ndots——K8s 形态）

  • 绝对名（尾点）直查。
  • 相对名：点数 ≥ ndots → 先绝对后 search 域逐个展开；点数 < ndots → 先 search 后绝对。
  • 某候选 NXDOMAIN → 尝试下一候选；全部 NXDOMAIN → 返回最后一个负向结论（不抛）。

2.3 安全位（security-aware 契约——RFC 4033 §8）

  • 查询带 EDNS0 OPT（EdnsPayloadSize 缺省 4096）；RequestDnsSecOk=true 置 DO 位。
  • 应答 AD/CD 位随 DnsSecurityStatus 完整外显——AD = 递归层已验证的可信标注， 采信与否是消费方决策（stub 不做签名验证链）。

3. 边界与失败语义

边界 语义
阻塞式异步 全异步族；查询内部有超时/重试——调用方传 ct 级联取消
单跳 UDP 应答 事务 ID 不符的错包丢弃续收（≤4 个）；超时即该次尝试失败
压缩指针 跳转上限 100 + 单调回指守卫——环/越界/保留位型报文拒收（IOException）
authority/additional 节 不消费（stub 只取应答节）——SRV target 的地址请另行 A 查询（走缓存）
resolv.conf 变更 进程级一次自举——变更随进程重启生效（F9 漂移语义针对记录/端点，走 TTL 缓存过期）

永久 Non-goal（#498 裁定）：DNSSEC 签名验证链（RRSIG/DNSKEY/DS/NSEC·NSEC3）与递归迭代解析 （递归解析器职责——stub 以 AD 位消费验证结论）；DNS server 面（权威/转发/AXFR/RFC 2136 动态更新）； mDNS/LLMNR/DNS-SD 组播族（独立协议族，非 DNS 单播子集）。

4. 反模式

  1. 自己缓存解析结果——resolver 内建 TTL 缓存，外层再缓存 = 双份过期语义；
  2. 忽略 DnsSecurityStatus.ResponseCode——NxDomain 是正常返回（记录集空），不是异常，消费方必须判码；
  3. 拿 SRV target 直接当 IP 连——target 是主机名，须经地址解析（ResolveAddressesAsync 走缓存）。
