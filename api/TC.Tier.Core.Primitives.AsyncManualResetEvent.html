    Class AsyncManualResetEvent

    基于 PooledValueTaskSource 的可复用异步手动重置事件。

    语义对标 ManualResetEventSlim，但暴露 ValueTask 异步等待入口，常规等待路径零堆分配。

    多 waiter 广播：Set() 唤醒当前所有等待者；事件保持 set 状态， 后续 WaitAsync(CancellationToken) 立即返回，直到显式 Reset()。

    Remarks

    实现要点：ManualResetValueTaskSourceCore<TResult> 是单消费者模型， 不能被多个 waiter 共享（多 waiter 同 version 挂起时，先完成的 waiter 调 GetResult 会使后续 waiter 的 OnCompleted 抛 InvalidOperationException）。故本实现为每个等待者分配独立的 PooledValueTaskSource（双层池化）。

    1:1 快路径（#PERF-002）：首个 waiter CAS 抢占 _singleWaiter 单槽——高频 1:1 唤醒免 WaitNode 分配、免锁；单槽被占时溢出回退 waiter 链表（多 waiter 广播语义不变）。 Set 侧先 volatile 写 isSet 再 Exchange 单槽：waiter 抢占槽后的 double-check 读到 true 即安全返回， 无丢信号窗口。

    唤醒语义与零分配（#PERF-002）：WaitAsync(CancellationToken) 是非 async 方法（无状态机装箱）， source 归还挂在 GetResult 的清理钩子（OnCleanup）上——真实唤醒路径零分配。唤醒调度模式可配： 默认线程池异步（安全）；runContinuationsAsynchronously: false 时 Set() 在锁外 内联完成等待者续体（对齐 SemaphoreSlim.Release，省一次线程池往返）——⚠️ 仅限 Set 调用点不持锁的场景 （持 SpinLock 等不可重入锁时内联续体会自死锁，如 SkipListPriorityQueue 的节点锁，故默认异步）。

    source 归还策略：每个 waiter 的 PooledValueTaskSource 在 Set() 唤醒后由本类自动归还到池（SetResult 后 core 进入完成态， 归还时的 Reset 只推进 version，不影响已发出的 ValueTask 的 awaiter 读取结果—— 因为 awaiter 已通过 OnCompleted 捕获了 continuation，SetResult 已触发其恢复）。 取消的 waiter 的 source 由 AttachCancellation(CancellationToken) 的 回调完成，同样会被 Set 时的链表遍历归还（若取消发生在 Set 之前，source 已从链表摘除并归还）。

    WaitAsync(CancellationToken)

    异步等待事件被 set。若已 set 则同步完成（零分配）。

    未 set 时等待者入队；被 Set() 唤醒或被取消时出队。

    ★ 两种唤醒模式 + 完成先于注册安全协议（#PERF-002）： Set() 一律经 MarkOrComplete() 完成 source—— continuation 未注册时仅标记，注册（OnCompleted 转发处）即补完；从结构上消除 ManualResetValueTaskSourceCore 的 CompletionSentinel 崩溃类（裸 SetResult 完成未注册 source 必抛）。

    • 默认（线程池异步调度，Set 可持锁）：async 方法 + 锁内入队（V1 同形）——真实唤醒 付一次状态机装箱 + 线程池往返（~800ns）。
    • 内联模式（runContinuationsAsynchronously: false）：非 async 实现 + 单槽快路径 + GetResult 清理钩子（零装箱、Set 调用者线程内联续体、真实唤醒 ~80ns）。 ⚠️ 仅限 Set 调用点不持锁场景（持 SpinLock 等不可重入锁时内联续体会自死锁）。
