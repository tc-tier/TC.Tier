EntryLogSettings

EntryLog 专属配置——通用 entry 顺序日志（WAL 典型用途）。

★ group commit 三维度阈值（EntryLog 的核心持久性调度，见 Structures-log-rewrite-design.md §0.6）。

★ group commit 建立在引擎组合之上（默认 Mode C：DIO + None）：

Append 攒批（pwrite 到 CommittedTail，未 fsync）→ 三维度阈值任一满足触发提交执行链：

engine.Flush(commitTail) 落盘 → CommittedOffset = commitTail → meta.Commit() 记录边界。

★ 崩溃窗口 = 提交触发间隔内的写入量（持久性底线）。

★ 三场景靠阈值配置表达（无需枚举选模式）：

- 典型 WAL（默认 1ms/64KB/1000）：三维度兜底。

- 单条强制（全设 0）：每次 Append 立即触发；宜配 PersistenceMode.WriteThrough（Mode D，逐写已落盘）。

- 手动/2PC（Interval=InfiniteTimeSpan + 阈值很大）：不自动提交，靠 CommitAsync / TransactionLog 驱动。

★ 三维度阈值仅用于构造默认 TC.Tier.Runtime.Structures.Log.GroupCommitPolicy（EntryLog 构造 commitPolicy 参数为 null 时启用）。

LogBase

LogBase 批量追加 partial——★ 地址空间窗口 + 页攒批模型。

inline 写页缓冲（本地跟踪 _pageUsed），页满走让渡轨（TC.Tier.Runtime.Structures.Log.LogBase.FlushPageYield： 当前页让渡给异步刷盘管线、立即切另一页继续写——页满不阻塞写线程，唯一等待点 = 双页都在途的 背压），Dispose 时回写宿主状态。

★ 双形态：Append(ReadOnlySpan<byte>)（同步——页满让渡零阻塞，背压同步等=诚实语义）+ AppendAsync(ReadOnlySpan<byte>, CancellationToken)（ValueTask——快路/让渡路同步完成，仅背压真异步）。

★ 消除 per-entry：EnsureNotDisposed / ComputePaddingLength / OnAppended / EnsureSpace*。

★ 单写者纪律（顺序读依赖批内物理连续性）：AppendAsync(ReadOnlySpan<byte>, CancellationToken) 背压慢路的 Monitor.Exit 窗口内禁止其他写者插队 Begin——批协议的消费形态 = 单写者 （raft 适配器 = wal 唯一追加方）。

Log 基类配置（abstract）。通用字段被所有 Log 实现类共享。

★ 心智模型（见 Structures-log-rewrite-design.md §0）：IO 底层 = 持久化的内存。 Log 不碰段/对齐/落盘细节，只配 IO 模型 + 持久化模型 + group commit 阈值。

★ 每个实现类有专属 sealed Settings 子类（对齐 Metadata/Mirror 的 Settings 范式）， 承载该实现类独有的配置（如 EntryLogSettings 的 group 提交配置）。

LogBase.AppendBatch

批量 ref struct——inline 写页缓冲，本地跟踪 _pageUsed，Dispose 时回写宿主状态。

★ 消费纪律：批（ref struct）绝不跨 await 持有（持写锁）；AppendAsync(ReadOnlySpan<byte>, CancellationToken) 背压慢路的 await 发生在宿主侧（TC.Tier.Runtime.Structures.Log.LogBase.AppendBatchSlowAsync(System.Byte[],System.Int32,System.Int32,System.Int32,System.Int32,TC.Tier.Contracts.Storage.LogicalAddress,System.Threading.CancellationToken)）——返回后批把写锁交还 （孤儿认领协议），消费方的下一个批操作在当前线程重新认领，任意续体线程安全。
