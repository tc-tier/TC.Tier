★ 恢复阶段（持有者中立——所有 LifecycleBase<THints> 派生类共享同一套通用恢复状态语义）。

严格顺序推进，不可回退：NotStarted → Recovering → Completed（成功）/ Failed（失败）。

★ 恢复进行中的细分步骤（读 meta/配置、扫数据源定位边界、应用恢复结果等）不另设阶段枚举—— 一律处于 Recovering，由 RecoveryProgress 的 Percent(0-100) + Detail 表达粒度。这样枚举对任何持有者（IO 引擎 / Log / Ring / Index / Metadata / Blob）都通用， 无需按域分别解释阶段语义。

★ 生产代码不按 Recovering 内部的细分做分支判断——细分仅供进度展示； 控制流只认终态（Completed/Failed/NotStarted）。

public enum RecoveryPhase

Fields

Completed = 2

恢复完成，持有者可投入使用（IsReady=true）。

Failed = 3

恢复失败（meta 校验失败、锚点无效等致命错误，非首次启动的空库）。 异常存 RecoveryState 的 Error 字段可观测。

NotStarted = 0

未开始（构造后初始状态）。

Recovering = 1

★ 恢复中（后台 task 正在跑：读 meta/配置、扫数据源、应用恢复结果等，全归此态）。

        <p>细分粒度（在哪一步、进度多少）由 <xref href="TC.Tier.Contracts.Lifecycle.RecoveryProgress" data-throw-if-not-resolved="false"></xref> 的 <code>Percent</code> + <code>Detail</code> 表达，
          不再枚举化。持有者在 <code>RaiseProgress</code> 时上报有意义的 detail 文案 + 推进的 percent 即可。</p>
