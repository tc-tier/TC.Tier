    Class BackgroundWorkerLoop

    通用长生命周期后台循环骨架（第一层——循环骨架，无队列）。与业务无关。

    ★ 封装：执行器（注入 TaskScheduler（如 IsolatedTaskScheduler.Shared）或 null=公共池 + ConsumerCount 多消费者扇出——消费者是协作跑在调度器线程上的循环 Task，不是线程数）+ 幂等启停 + 超时等待退出 + CAS 防双 Dispose + 单周期异常隔离。

    ★ 子类实现 RunOneCycleAsync(CancellationToken)（一个工作周期）+ 信号源选择（见 worker-loop-unified-design.md §5）。

    ★ 自身 IDisposable——LifecycleBase<THints> 内建持有时， Dispose 统一编排 Stop + WaitForExit（见 worker-loop-unified-design.md §4）。

    ★ 多消费者：ConsumerCount 个执行体共跑同一循环（各自 RunOneCycleAsync(CancellationToken)）， 常用于事件驱动队列的多消费者 drain（BackgroundWorkerLoop<T> 内建优先级队列 + counting-semaphore 逐项公平唤醒，见 BucketPriorityQueue<TPriority, T>）。默认 1 = 向后兼容。

    TaskScheduler scheduler

    执行器调度器：null=Run(Action)（公共池——低频 worker，如 CpuSampler/meta flusher）； 非 null=注入（如 Shared——高频/关键 worker，隔离公共池）。 ★ 线程数 M 由调度器决定，与 consumerCount 彻底解耦；本类不 own 调度器（注入方管生命周期）。

    TimeSpan? exitTimeout

    MaxConsumerCount

    consumerCount 上限 = max(ProcessorCount*4, 16)。

    ★ 依据：消费者是协作跑在调度器线程（M ≤ ProcessorCount）上的循环 Task、不是线程数—— N 超过可能并行度的 4 倍只增内存/调度开销、不增吞吐。

    ★ 超界 ctor 直接 throw（fail-fast）——防"外部传巨大 N → 静默卡死无人知因"的失效模式。 需要更高并行度应增大调度器线程数（ThreadCount）而非 consumerCount。

    RunOneCycleAsync(CancellationToken)

    一个工作周期（子类核心实现）。

    ★ 典型实现：取一批任务（或等信号源）→ 处理 → 返回。

    ★ 返回 false 则停止循环（如 EOF / 显式终止条件）。多消费者下：单个消费者返回 false 仅自身退出， 不影响其他消费者（如需全停，子类自行 Stop()）。

    ★ 抛异常不杀 worker——异常走 OnCycleError(Exception) 钩子，循环继续下一周期。

    ★ 收到 OperationCanceledException（Stop 触发的 cts.Cancel）视为正常退出，不进 OnCycleError。
