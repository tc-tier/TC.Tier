Namespace TC.Tier.Core.Net.Transport

Classes

DnsPeerDiscoverySource

DNS 发现源（二期-F8/F9——well-known 引导节点的主机名 A 记录解析）： NodeId 静态已知（集群引导配置），端点 = 解析地址 + 配置端口；每次 Discover 重解析 （DNS 漂移/端点迁移跟随——F9 的最小实现面）。

FilePeerDiscoverySource

文件发现源（NETGAP-041——K8s ConfigMap/Consul KV 导出文件的常见形态）： 每行 hexNodeId=host:port，# 注释行跳过；每次 Discover 重读文件（热载）。

★ 零 BCL IO 纪律（设计 §11）——文件访问经 IFileSystem，不自持 BCL File。

PeerDiscoveryService

发现汇聚服务（二期-F8）：周期轮询全部源 → 合并 → AddPeer(NodeId, IPEndPoint) （新增/端点更新；不移除——add-only 语义见 IPeerDiscoverySource）。

TopologyMap

拓扑感知（二期-F1 NETGAP-017——成员位置属性 + 放置约束/反亲和的判定面）： 成员 → 位置标签（rack/zone/region 任一粒度，语义归使用方）的映射与故障域判定。

★ 约束判定：反亲和（任意两成员不同故障域）、故障域计数（跨 AZ 分布度）—— 供装配/再平衡/放置策略消费。位置属性装配期供给（运行期静态——服务发现动态化归 F8/F9）。

TransportOptions

传输装配选项（spec-12 §4.5——不可变 record，With 派生；运行参数零写死：缺省只服务零配置起步， 装配期全部可覆盖；协议常量除外（帧头 16B/PayloadLen 上限/CorrId 8B = 线格式定数））。

★ 地址表 = 装配期静态注入（NodeId → IPEndPoint）；Core.Net 不做服务发现 （发现是 p2p 层职责）。动态成员 = 协议域配置变更后重建本传输。

★ UDP 数据报端点：UdpListenEndPoint 非空 = 绑定 UDP 端点并经握手通告（特性位 bit1，Negotiate 帧承载）；null = UDP 关闭。

Interfaces

IPeerDiscoverySource

服务发现源（二期-F8 NETGAP-041——引导/发现的可插拔源）：每次 Discover 返回当前已知的 (NodeId, EndPoint) 集合。实现归使用方/外部系统（K8s headless DNS、Consul KV 导出文件、 静态配置）——Core.Net 只定义源契约与汇聚循环。

★ 语义：发现为 add-only——汇聚仅 AddPeer 新增/更新端点；移除归退役/治理编排 （D8/C2），发现源缺失项不触发移除（避免源抖动误删在途成员）。

IPeerRegistry

运行时动态成员表（二期-C2 §5.3）：物理可达性的增删面——组内成员集合始终以各组 ClusterConfig 为准（§2.3 不变量⑤），本表只管"谁能拨/拨到哪"。

★ 语义（§5.3）：AddPeer 自端 = 抛；同 ID 换端点 = 更新（下一拨号轮生效）； RemovePeer = 出表 + 停拨号循环 + 入站黑名单（运行时易失）+ 可选断链；未知 ID 幂等。

ITransportFaultInjector

传输故障注入器（spec-12 §9.2——传输常设面，对抗场景族在任一介质等价复跑的机制基础， 非测试代码泄漏）。

注入语义均为"定向"（节点对级）——延迟/分区/丢包各管各的注入维度，可叠加。
