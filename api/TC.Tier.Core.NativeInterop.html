    FileMetaSupport

    文件系统对扩展属性（xattr/ADS）的支持程度——平台中性的底层探测结果。

    ★ 归属 NativeInterop 层（internal）：描述底层文件系统是否支持把段元信息附着到段文件本身 （Linux xattr / Windows NTFS ADS / macOS xattr），由 TC.Tier.Core.NativeInterop.FileNative 探测得出。 **不公开**——上层 Device 层消费时据此选择 meta 写入策略（xattr 主路径 vs 异步边车回退）。

    ★ 二态语义（简化版，对比 UnbufferedIoSupport 的四态）：

    • Supported：文件系统支持 xattr/ADS，写入 + 读回校验成功——主路径走 per-segment 扩展属性（与段文件同 inode，天然一致，段级原子）。
    • Unsupported：文件系统不支持（FAT32、某些网络盘、容器 overlayfs 限制）， 或探测时异常——回退异步边车后台写（device 级集中文件，崩溃容忍）。
    • NotProbed：尚未探测（理论不应出现，Initialize 必探测一次）。

    ★ 探测策略与 UnbufferedIoSupport 一致：try/catch 包裹，失败保守降级（安全侧 倾斜，不支持时走异步边车更稳，避免主路径写 xattr 反复失败拖慢）。

    UnbufferedIoSupport

    文件系统对无缓冲（unbuffered / direct）I/O 的实际支持程度——平台中性的底层探测结果。

    ★ 归属 NativeInterop 层（internal）：描述底层文件系统物理能力，由 TC.Tier.Core.NativeInterop.FileNative 探测得出。**不公开**——上层 Device 层消费时通过映射转成公开的 DirectIoMode，避免下层（NativeInterop）反向依赖上层（Device）的层泄漏。

    ★ 三态语义：

    • Supported：文件系统真正支持 unbuffered I/O（Windows NTFS/ReFS、Linux ext4/xfs/btrfs）， open 成功且 flag 实际生效。
    • BestEffort：文件系统接受 unbuffered hint 但不保证（macOS F_NOCACHE、未知 FS）， 对齐非强制。
    • Ignored：文件系统忽略 unbuffered flag（Linux overlayfs/tmpfs/ramfs 等容器常见 FS、 Windows 网络重定向器/SMB），open 成功但 flag 被静默吞掉——走 page cache。
    • NotRequested：上层未请求禁用缓冲（disableBuffering=false），无需探测。
