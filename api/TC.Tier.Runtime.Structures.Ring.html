    RingBase<TKey>

    RingBase 寻址 partial——热路径 TryAllocate/Seal/GetPhysicalAddress/GetSpan/GetInfo。

    ★ FASTER hybrid log 地址模型（照 AllocatorBase，仅 long→LogicalAddress + 引擎 API）：

    - 地址单调递增，永远向前；不回退（不需要 ReclaimTail，那是 Log 变长页才用的）。

    - 内存固定 PageCount 个 native 槽，slot = pageSeq & PageCountMask 循环复用。

    - 写满一圈淘汰旧页（head 推进 FreePage），tail 继续 append（地址继续增长）。

    ★ 引擎地址空间提供 100% 确定的地址。Ring 基于 _dataStart + GetDistance 做 100% 正确寻址。

    ★ _dataStart 构造时 Allocate 确定（GetDistance 锚点）。pageSeq = GetDistance(_dataStart, addr) / PageSize。

    ★ 地址运算只用 CalculationAddress/GetDistance（§8 铁律，不碰 Offset 算术）。

    RingSettings

    Ring 基类配置（abstract，{ get; init; } 不可变，对齐 LogSettings/BlobSettings）。

    ★ 心智模型（engine-migration-rewrite.md §0/§1）：IO 底层 = 完全屏蔽复杂操作的持久化内存。 Ring 不碰段/对齐/落盘细节，只在引擎地址空间上做页池几何（mutable→readonly→flushed→evicted 状态机）+ 环形驱逐。

    ★ 通用设备字段（RootDirectory/DeviceName/SegmentSize/DeleteOnClose/DirectIoMode/PersistenceMode/RecoverDevice/Engine） 对齐 LogSettings 同名字段——4 基类统一新引擎模型。Ring 专属字段（PageSize/MemorySize/MaxPageCount/MutableFraction/ Preallocate/OverflowPolicy/MinOverflowSize）是 Ring 独有。

    ★ PageCount 是派生量（= MemorySize / PageSize），不在 Settings 里直接配。

    参见 base.md §2.8。
