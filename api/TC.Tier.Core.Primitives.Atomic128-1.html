标准 128 位 CAS 单槽封装——16B 对齐背板 + 能力探测降级 + 裸读不撕裂。

★ 消除各处（TailWatermarkSlot/IndexBase/AsyncPriorityQueue）重写的 128 CAS 样板：16B 对齐分配 + Unsafe.As<T,Int128> reinterpret + CompareExchange(ref Int128, Int128, Int128) + 能力探测 + lock 降级。

★ 统一对齐保证：托管数组（T[]）只保证 8B 对齐，无 16B 对齐保证—— lock cmpxchg16b 要求 16B 对齐，未对齐会 #GP（硬件异常）。本封装用 AlignedMemoryManager（64B 对齐 ⊃ 16B，且独占缓存行避 false sharing）做背板， 从根上消除"碰巧 GC 分配对齐"的定时炸弹。

★ 标准用法（参考 TailWatermarkSlot）：CAS 循环 = Read() 裸读当前 → 业务条件检查 → 算新值（含 ABA version）→ TryCompareExchange(T, T) → 失败 SpinWait.SpinOnce() 重试。

★ 能力探测 + 降级：native 128-bit CAS 不可用时（生产永不触发）退化到 lock， 行为与 native 路径完全一致（位精确）。测试钩子 _casEnabledForTesting 反射改写触发降级分支 （沿用 TailWatermarkSlot 旧约定）。

TryCompareExchange(T, T)

★ 128 位 CAS（位精确比较，含 ABA version 等所有位）——native 优先，降级 lock。

成功 = location==expected，写入 value 返回 true； 失败 = location!=expected，值不变返回 false。

⚠️ 位精确：与 LogicalAddress.Equals（只比 SegId+Offset）不同——CAS 含 Extension(version) 全部 16 字节。调用方做 ABA 防护时须在 expected/newValue 里携带正确 version。

★ 失败不回写观察值（与 CompareExchange(ref Int128, Int128, Int128) 公开语义一致）—— 调用方在 CAS 循环里自己 Read() 重读。

TryCompareExchangeUnsafe(T, T)

★ 快路径 CAS——跳过 TC.Tier.Core.Primitives.Atomic128`1.CasEnabled/IsDisposed 检查，直接 native 128-bit CAS。

⚠️ 调用方须保证：(1) native 128-bit CAS 可用（TC.Tier.Core.Primitives.Atomic128`1.CasEnabled 为 true）； (2) 未 Dispose()。违反 → 未定义行为（disposed 后 AV / native 不可用抛异常）。

★ 用于热路径榨性能——省 TryCompareExchange(T, T) 的 ~3.6ns 运行时分支开销 （CasEnabled 读 + Isdisposed Volatile.Read）。TailWatermarkSlot 等已知"disposed 顺序保证 + native CAS 一定可用"的场景用本方法。

位精确比较、失败不回写——语义同 TryCompareExchange(T, T)（仅少两个前置检查）。
