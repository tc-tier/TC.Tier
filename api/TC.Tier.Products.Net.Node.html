TierFsIdentityStore

IIdentitySource 的 TierFs 身份文件适配器（spec-12 §8.3 / D6-T3——Core.Net 零文件 IO 的组装层落地，两个核心在组装层汇合）：身份文件落使用方指定卷/路径，四介质任意 （测试 memory 卷 / 生产 local / 云 network）。

★ 文件布局（本适配器私有，25B 定长）：[Magic "TCID" 4B][Ver 1B][NodeId 16B][CRC32 4B LE]—— CRC 覆盖 Ver+NodeId；Ver 留 W-Security 密钥材料升级位。

★ 契约：首次 LoadOrCreateAsync(CancellationToken) 生成（NewRandom()）并原子保存 （temp 写全 + Flush → rename 覆盖，半写不可见），此后加载同一身份——NodeId 跨重启稳定 （成员表/votedFor 绑定前提）。文件损坏/截断 = 身份断裂风险，fail-fast 抛 FileIOException——禁静默重生成（重生成等于静默换节点身份）。

★ 一个路径 = 一个节点进程（进程内并发经 TC.Tier.Products.Net.Node.TierFsIdentityStore._gate 串行；跨进程同路径并发创建 = 部署误用，不做跨进程互斥）。权限收紧（§8.3——凭据不是普通数据）：IFileSystem 无权限语义面， 随 W-Security（密钥材料入文件）一并收口。

组合根文件系统（测试 memory 卷 / 生产 local / 云 network 四介质任意）。 身份文件路径（一个路径 = 一个节点进程）。
TierRaftNode

TierRaftNode——raft × Tier 产品装配节点（D6 产品接线收口件）：存储（TierWal → TierWalRaftStore）、 协议（RaftStateMachine + ApplyPipeline）、多源与反熵（SwarmSync + SwarmAntiEntropy）、 宿主调度（快照压缩 + 反熵周期 + 换届接线）——一个入口装配完整产品节点。

★ 装配链：TierWal.Builder → TierWalRaftStore → ApplyPipeline(业务状态机) → RaftStateMachine → 传输（调用方组装根——ClusterTransport/InProcess 皆可）；宿主循环承载三件调度：

① 快照压缩（全角色）：日志增长 ≥ SnapshotGrowthThresholdEntries → SnapshotAsync(CancellationToken)（一体：镜像 [Head..N₀] + 截头——raft 日志压缩惯例）；

② 快照发布（全角色，Swarm 装配时）：N₀ 变更 → 块化内容挂源（holder 侧——供给拉取与对账）；

③ 反熵（仅 leader 发起、对端轮转——SwarmOptions.AntiEntropyInterval 契约）： 与对端比对已发布快照内容 → 漂移块定向修复（机制 = RunOnceAsync(ISwarmBlockSource, NodeId, SwarmManifest, CancellationToken)）；

★ 换届接线：LeaderChanged false → OnLeaderLost() （持有表清空）+ 反熵停发；true → 恢复发起资格。非 leader 持基线时向已知 leader 上报（启动/换届触发③）。

TierRaftNodeBuilder

TierRaftNode 装配器（D6 产品接线收口——三段式惯例：Create → 链式配置 → StartAsync 一次成型）： 传输二选一——①注入现成传输（WithTransport(IProtocolTransport)——嵌入式同进程/调用方自组装）∥ ②内建 ClusterBuilder 组装（WithClusterTransport(IPEndPoint?, IReadOnlyDictionary<NodeId, IPEndPoint>, uint, Func<TransportOptions, TransportOptions>?)——TCP 真部署形态， 传输配置走 B 方案全旋钮口）；都不给 = fail-fast 教用法，不给默认形态（装配形态显式）。

★ 组合而非复制：内建形态经 Core.Net 装配器组装传输（NodeEndpoint 承载——机制/传输 生命周期随之归节点），产品层不重写传输拼装样板。

★ 兼容：静态 StartAsync(NodeId, IFileSystem, IProtocolTransport, ClusterConfig, IStateMachine, TierRaftNodeOptions?, ILogger?) 保留为薄壳（签名不变——存量 调用/测试/探针零改动），内部走本装配器。

TierRaftNodeOptions

TierRaftNode 装配配置（不可变 record + With 链——装配惯例同 TierWalOptions）。

★ 全部旋钮缺省即产品形态：TierWal 生产默认（DIO hints/组提交三维度）、 raft 默认策略、 多源/反熵与宿主压缩调度缺省关闭（按部署显式开启）。

TierRaftWitnessNode

TierRaftWitnessNode——witness（见证者）产品节点（三期-F2 装配面）： 共识投票成员（计入选主/提交多数派）而不存全量数据——高水位断言流（WitnessHighWaterStore） 代替日志体、无状态机、无快照，永不成为 leader（MongoDB arbitrator / PolarDB witness 同位）。

★ 与 TierRaftNode 的分工：witness 无日志体/无 apply 管道/无 Swarm/ 无宿主调度（快照压缩与反熵均不适用）——完整产品节点的装配链在此不成立，故独立轻量形态； 引擎语义（投票/断言流/不自荐）同一 RaftStateMachine。

★ 引导：空盘 witness 经 TierRaftNodeBuilder.WithJoinAsWitness 加入既有集群 （JoinReq AsWitness 档——leader 受理即配置提交，断言流随后到达）；本地配置 [self witness] 是引擎 witness 门的依据（IsWitness——内容不落盘、投票不自荐）。

TierRaftResourceProfile

节点资源档位（装配期一次定性——展开为具体组件参数，热路径零分支）。

★ 展开语义 = 只补缺省：显式 WithWorkerScheduler(IsolatedTaskScheduler?) 注入 恒优先；LowResource 在 Wal 配置未被定制（== Default）时全量 生效预设（引擎调度器收敛到进程级共享单例 + 几何收缩：页 1MB/快照段 8MB/worker 消费者 1）； Wal 已定制 = 用户主权——仅补调度器缺省，几何不动。
