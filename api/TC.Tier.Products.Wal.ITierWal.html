TierWAL——协议中立 WAL 产品（raft/p2p 的存储中线）。

★ 定位：存储侧把 raft 协议要求的全部持久化语义做齐但内容零知识——entry 内容不解析、 元数据内容不解析（Opaque 槽）；raft/p2p（TC.Tier.Products.Net）是纯消费方，直接接线即可。

★ 能力映射（底层 EntryLog 已实现，TierWAL 只封装 + 自定 opaque 容器布局）：

- 追加：组提交 AppendBatchAsync(IReadOnlyList<ReadOnlyMemory<byte>>, CancellationToken)（raft 攒批）/ 单条 AppendSingleAsync(ReadOnlyMemory<byte>, CancellationToken)

- 显式提交 CommitAsync(CancellationToken)（raft 同步点：一次 fsync = 一批持久化）

- 截断：TruncatePrefixAsync(long, CancellationToken)（头压缩，与写并行）/ TruncateSuffixAsync(long, CancellationToken)（冲突修正）

- 重放 ReadFromAsync(long, CancellationToken)（随机起点顺序读，index 定位 = 段表二分 + 段内扫帧计数）

- 元数据 Opaque 槽 WriteMetaAsync(ReadOnlyMemory<byte>, CancellationToken)/ReadMeta()（term/vote/config 原子替换）

- 快照导出/导入 ExportSnapshotAsync(CancellationToken)/ImportSnapshotAsync(CancellationToken)（一致性点 N₀ 进帧 Header）

★ index 承载（设计 §8.7）：raft 日志连续无空洞——index 由"起点 + 顺序计数"推导， 帧内零 index；段 anchor 表随 opaque 原子落盘（恢复 O(1) 读全表）。

★ 双水位：AllocatedIndex（内存计数，含攒批窗口）/ PersistedIndex （最后显式提交水位——raft 语义的 last persisted index 可信下限，自动提交只提前落盘不推进）。

SnapshotAsync(CancellationToken)

raft 日志压缩（一体：主数据镜像生成 → 本地快照存储 → 增量压缩截断）。

★ 快照内容 = 主数据 [Head..N₀] 的原始条目帧流（WAL 自己从主数据生成——非 raft 状态机镜像； N₀ = 调用时 PersistedIndex——只含已持久化）；随后 TruncatePrefixAsync(long, CancellationToken)(N₀+1) 压缩已镜像段 （先快照后截断——被截区有快照覆盖）。

★ 本地存储恒为内部快照结构（IncrementalSnapshot——raft 冷启动必须本地载入）； 传输（Export/Import）经注入的 IAsyncTransferPersistence（默认回落 = 内部快照结构）。 调用时机 = leader 定期压缩（raft 惯例——低频）。
