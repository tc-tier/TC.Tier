LifecycleBase<THints>

通用生命周期骨架基类（Core 层）。数据结构基类与 IO 引擎基类共同继承本类，获得统一的

★ 实现 ILifecycle<THints>——统一"同步 void Initialize 启动后台恢复 + 观测/等待"模型， 详见 src/TC.Tier.Core/docs/lifecycle.md。★ Initialize 是类面方法（不在 ILifecycle 接口面）—— 设计决策接口面消除：启动入口由各持有者自己的装配面提供（引擎 = StorageEngineBuilder.Start）， 接口只保留观测/等待；结构层内部组合面仍经具体类型调用。

★ 内建 Resources（ResourceGroup）——统一资源释放， 子类构造期/钩子里 Resources.Add(...)，Dispose 自动统一转发（消灭各基类 _owner/_disposables 样板）。

★ Initialize 是固定模板（IO 引擎与数据结构共用同一套 On 钩子模式）： CAS 闸门 → OnInitializeBegin() → CreateRecovery() → 订阅进度事件 → 后台恢复 task。 子类只 override 钩子，不改流程。

RecoveryBase<THints>

★ 通用恢复模板基类（Core 层）——模板方法模式：钉死 RecoverAsync(THints, CancellationToken) 编排， 子类只 override OnRecoveryCoreAsync(THints, CancellationToken)（真正的恢复算法）。

与 LifecycleBase<THints> 对称：LifecycleBase 钉死 Initialize 的 前→中→后三阶段，RecoveryBase 钉死 RecoverAsync 的五步编排 （TryEnter → WaitForDependencies → Start → Core → Complete → MarkReady）。两者合起来构成 "生命周期 + 恢复" 的完整通用骨架——继承 LifecycleBase + 注入 RecoveryBase 派生实例即可。

★ 消灭各 IRecovery<TRecoveryHints> 实现复制粘贴的状态机样板： CAS 三态闸门 + _state + MarkReady/Reset/RaiseProgress/ TryEnterRecovering + Start/Complete 钩子 + RecoverAsync 编排 + 失败置 Failed——全部收进基类。

★ OnRecoveryStart()/OnRecoveryComplete() 由本模板在 RecoverAsync 内 保证调用（串行接在 Core 前后），不再是各实现手动调的"伪钩子"。当前为 public virtual 以满足 IRecovery 接口契约；待接口瘦身（移除这两个方法）后收为 protected virtual。
