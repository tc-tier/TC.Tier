HazardPointers 原语——无锁结构的退休安全回收层（与 LightEpoch 同层级的通用机制）。

语义：读者在解引用前 TryProtect(HazardRegistration, int, ref long, out long)（发布 + 验证来源未变）取得对具体句柄的保护； 删除者物理摘除后 Retire(long, Action<long>)；Scan() 快照全部 hazard 槽，无指向者的退休项执行 reclaim（结构性恰好一次）并复用。

★ 获取纪律（设计 §3.3，正确性核心）：只发布不验证保护不了任何东西——扫描可能在发布前已过。 TryProtect 内建「发布 → 重读来源验证」，验证失败 = 正常竞态以新值重试，不构成错误。

★ 活性契约（设计 §3.4）：水位顺带扫描是策略非保证——依赖回收前进的调用方（槽池等）必须在 资源耗尽路径显式 Scan()（本原语在退休记录池耗尽时自动强制）。

★ reclaim 契约：恰好执行一次（结构性保证，禁止调用方假设幂等）；必须纯内存、无异常、 不阻塞。reclaim 内允许 Retire（扫描互斥可重入 + 分层快照缓冲，不自锁）。

★ 生命周期：.NET 无线程退出回调——长线程负责 Register/Dispose 配对；瞬态线程漏注销的后果是 退休滞留（悬挂 hazard，非内存损坏），由水位看门狗检测。

Scan()

扫描（整链交换私批——设计 §3.4）：① Exchange 原子摘走整条退休链（并发 push 只挂新链） → ② 快照全部 hazard 槽（排序）→ ③ 私批比对：无指向者执行 reclaim 并复用记录；幸存者 CAS 推回。

★ 恰好一次是结构保证：批次脱离共享链 + 交换原子 + 并发 Scan 经 _scanGate 串行 ——不依赖 reclaim 幂等。快照缓冲按嵌套深度分层（重入 Scan 各用各的，互不覆写）。

★ 快照读到瞬时值只会"多留一轮"不会漏保护：发布（release 写）与验证读的配对保证 "验证成功 ⟹ 后续扫描必见发布"。

public void Scan()

TryProtect(HazardRegistration, int, ref long, out long)

获取保护（发布 + 验证——正确性内建，设计 §3.3）。

语义：读 source → 发布 → 重读 source 验证未变；验证失败 = 正常竞态， 以最新值重试；source 为空返回 false。返回 true 时 slotRef 已验证新鲜， 此后才允许解引用。

★ 为什么必须有验证：只发布不验证，保护的是"过去读到的值"——扫描可能在发布前已过 （读者读边 → 删除者摘除+退休+扫描+回收 → 读者才发布 → 解引用读到复用后数据）。验证读返回旧值 ⟹ 摘除尚未发生 ⟹ 其后的扫描必见本次发布。与消费方"先物理摘除后 Retire"的程序序配对成立。
