    AsyncPriorityQueue<T>

    异步优先队列——基于 lock-free 跳表（Fomitchev–Ruppert marker 删除协议）。

    ★ 高并发入队/出队 O(log n) 平均复杂度；出队时队列为空则异步等待或取消。

    ★ Route A 正确性基线（根因档案决策）：回归论文前提世界—— 边存直接对象引用 + marker 节点表达逻辑删除（单引用 64 位 CAS，无 128 位打包）、 节点 fresh 分配交 GC 回收（不池化、不 epoch、不 Id 寻址）。论文不变式 I1~I5 由构造消除， 不再自证回收协议。性能代价：每次入队一次 Gen0 分配（LOH 无压力）。详见 SkipListPriorityQueue<T>（锁基变体）与 docs/async-priority-queue-root-cause.md。

    marker 协议要点：victim 的 Forward[L] 被 CAS 成 AsyncPriorityQueue<T>.Marker （marker.Next 持真实后继）即"已逻辑删除"；物理摘除 = 前驱边 CAS 绕过 victim 直连 marker.Next。marker 永不被改写，victim 摘除后整体交给 GC——并发读者永不会读到回收后的节点。

    ★ 并发语义：多生产者安全；多消费者不丢不重，但并发出队时"最小元素"判定是 竞争性的（各出队以各自 mark CAS 为线性化点），严格最小序需要单消费者（或 SkipListPriorityQueue<T> 的持锁 DeleteMin）。

    ★ DEBUG 构建内置链校验器（key 严格递增 + 成环护栏），每 64 次操作自动巡检， 测试可显式调 TC.Tier.Core.Collections.AsyncPriorityQueue`1.ValidateInvariants 定点取证。

    AsyncQueue<T>

    异步生产-消费队列。基于 ConcurrentQueue<T> + 池化等待节点， 常规路径（队列非空时出队、入队唤醒）零堆分配。 出队发现队列为空时，租用独立完成源挂入等待链；入队时唤醒链首一个等待者。

    注意：本类不是通用 Channel，不支持单消费者背压 / 完成（Complete）等高级语义。 适合内核 IO 响应队列等"持续运行、永不关闭"的场景。

    BucketPriorityQueue<TPriority, T>

    离散枚举优先级队列——N 个 ConcurrentQueue<T> 桶，每桶对应一个枚举优先级。

    ★ 严格优先级：按枚举值升序扫描桶（值小先出），同优先级桶内 FIFO。

    ★ 无锁入队：ConcurrentQueue<T> 内部无锁实现。

    ★ lock-free 出队：扫桶 TryDequeue(out T)，单消费者接近 wait-free。

    ★ 适用场景：优先级是少量离散枚举值（如 4~16 级）。任意可比优先级用 SkipListPriorityQueue<T>。

    ★ 零分配：入队复用 ConcurrentQueue<T> 的分段池；等待复用 AsyncManualResetEvent 池化 source。

    ClockCacheV2<TKey, TValue>

    ★ CLOCK 近似 LRU 缓存 V2——组相联存储（set-associative，CPU 缓存教科书结构）。

    ★ 算法：容量拆为 sets × ways（默认 8 路）的固定槽组；查找/插入只扫描组内 ways 槽——miss 恒 ≤8 次读， 与负载因子无关（V1 开放寻址满载 miss 探测链发散至 681ns，V2 结构上不存在该悬崖）。

    ★ 淘汰：组内 CLOCK 二次机会（访问位 Interlocked CAS），≤2×ways 次操作，O(1)。

    ★ 命中率 90-99%（8 路组相联 ≈ 全表 CLOCK 的 90-99%，Zipf 实测 99.9% vs 100%）。

    ★ 线程安全：无全局锁，读路径纯无锁（Interlocked CAS 写路径）；并发语义与 V1 一致（尽力而为 Put）。

    ★ 热路径（hit/miss/update）零分配；Slot 数组 = capacity（内存 1×）。

    ★ 与 ClockCache（V1 开放寻址）并列：V1 甜区 = 铁律配置下（容量 ≥2× 工作集）极致热路径 （hit 3.7ns / update 2.9ns）；V2 = 任意负载延迟恒定、全路径反超 ConcurrentDictionary 基线 （hit 5ns / miss 7ns / 驱逐 70ns）。组偏斜会提前淘汰（均匀负载实际驻留 ≈ 容量 85-90%）。

    参见 src/TC.Tier.Core/docs/cache-and-compute.md。

    ClockCache<TKey, TValue>

    ★ CLOCK 近似 LRU 缓存——高性能、零分配热路径、线程安全（Interlocked CAS，无全局锁）。

    ★ 算法：环形数组 + 访问位 + 开放寻址法哈希（线性探测）。Redis/PostgreSQL/Windows 内存管理都用 CLOCK。

    ★ 命中率 90-95%（近似 LRU，工程足够）；淘汰 O(1) amortized（时钟扫描）。

    ★ 对齐 OverflowPool/PinnedBufferPool 的"底层组件+性能指标"范式。

    可复用：Ring 冷页缓存（ClockCache<long, AlignedMemoryManager>）、任意 key→value LRU 场景。

    参见 src/TC.Tier.Core/docs/cache-and-compute.md。

    OverflowPool<T>

    固定大小溢出对象池。并发安全（基于 ConcurrentQueue<T>）。

    ★ 指标：hits/misses/overflows 计数 + GetStats()（对齐 PinnedBufferPool 覆盖度）。

    容量上限为软约束（Soft cap）：高并发 TryAdd 下可能瞬时超出 size 几个， 因 ConcurrentQueue 的 Count 快照与 Enqueue 非原子。这对当前调用方（disposer 为 no-op， 超出项被丢弃）无正确性影响；如需硬上限须改用自旋锁或 CAS 容量跟踪。

    PinnedBufferPool

    高性能固定内存池，提供 pinned 数组与对齐原生内存两类池。

    SkipListPriorityQueue<T>

    通用并发优先队列——基于细粒度锁 skip-list（Herlihy 2006 lazy 版本）。

    ★ 任意可比优先级：支持任意 long 优先级值（值小者先出）。

    ★ 严格优先级 + 同优先级 FIFO：key = (priority, sequence)，sequence 单调递增保证同优先级 FIFO。

    ★ 细粒度锁：每节点一把 SpinLock，hand-over-hand 加锁，不同区间操作并行。

    ★ lazy validation：Peek/Find 不加锁（读 marked 字段）；Insert/DeleteMin 加锁后 validate（全层级—— 标记即完整摘除，marked 节点永为瞬态）。

    ★ 内存回收简单：unlink + 解锁后节点安全可回收（无需 epoch/hazard pointer）。

    ★ 定位：细分锁实现——任意 long 优先级 + 消费者较少的场景。严格优先级+FIFO 语义使同优先级尾插与 min 头摘是两个串行热点，吞吐上限由热点决定；无锁高吞吐场景用 AsyncPriorityQueue<T> （Route A 生产基线），离散枚举优先级用 BucketPriorityQueue<TPriority, T>。

    算法依据：Herlihy, Lev, Luchangco, Shavit. "A Simple Optimistic Skip-List Algorithm" (DISC 2006)。
