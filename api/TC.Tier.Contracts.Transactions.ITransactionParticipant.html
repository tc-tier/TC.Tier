    Interface ITransactionParticipant

    事务参与者接口——数据结构参与 2PC 原子提交的统一契约。

    4 基类（Ring/Blob/Log/Index）各自实现（基类自带），实现类零额外代码即可参与 2PC。

    LastPreparedSeq

    ★ 最近一次 Prepare 的 seq。恢复时判定悬空事务用。

    -1 = 从未 Prepare/未参与事务。

    恢复判定：LastPreparedSeq > 协调者 committedSeq → 悬空事务，丢弃；

    LastCommittedSeq 小于 committedSeq → 未同步，ConfirmCommitted 推进。

    Abort(long)

    ★ 新增（2PC 完整回滚改造）：回滚未提交的 Prepare。

    语义由各参与者 IO 模型决定：

    - Log/Ring/Snapshot追加部分：截断到 prepare 前水位（ReclaimTail）。

    - MetadataBase：内存窗口回退到上一已提交版本（零 IO）+ 尾截断。

    - MirrorBase：尾截断回退到上一 checkpoint。

    - IndexBase：no-op（纯内存参与者，回退 seq）。

    实现必须是幂等的——恢复时可能对同一 seq 多次调用。

    PrepareAsync(long, CancellationToken)

    ★ Prepare（预备）：把数据写到设备并 Flush（真正持久化），附 seq，但 lastCommittedSeq 不推进。

    数据持久化但"悬空"——未被 commit record 确认。崩溃在此后 Commit 前恢复时丢弃。

    ★ 必须包含 Flush——WriteAsync 不保证落盘。
