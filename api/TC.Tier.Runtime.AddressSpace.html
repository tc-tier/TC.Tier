    Namespace TC.Tier.Runtime.AddressSpace

    Classes

    Segment

    段对象（Segment）——承载数据文件的最小单位，负责水位管理、状态机、锁。

    SegmentFragmentation

    段碎片化统计——区间状态分布、空洞率、可合并建议。

    SegmentTable

    SegmentTable partial——地址算术 + 边界只读（文档 §3.3 §3.7）。

    ★ 纯计算 + 无锁原子读，无状态变更。

    Structs

    ExtentRecord

    段内区间记录。

    ★ State 是 byte（ExtentStateCode 编码：高4bit=Src + 低4bit=Phase），不是 enum。

    ★ LeaseRef 已移除——诊断跟踪移到段表诊断表（见 src/TC.Tier.Runtime/docs/segment-table.md 诊断接口）。

    Segment.ExtentReader

    ★ ref struct 持锁遍历器——using 自动释放 SpinLock，零分配零拷贝。

            <p>★ C# 12 兼容：ref struct 不实现 IDisposable，靠 pattern-based using 调 <xref href="TC.Tier.Runtime.AddressSpace.Segment.ExtentReader.Dispose" data-throw-if-not-resolved="false"></xref>。</p>

    SegmentEntry

    段条目——段 ID + 段规格的不可变组合（段表的公开条目形态）。

    SegmentSpec

    段规格：描述段的增长上限、最大偏移、稳定状态和最小偏移。

    SegmentTableSettings

    段表配置参数——用于初始化 SegmentTable。

    SegmentView

    段的只读值类型视图——段表对外的段信息载体，不含 segId（调用方已知）。

    ★ 段表对外不暴露可变 Segment 引用——所有状态变更经段表包装方法。

    ★ 值类型零分配；Hollow 哨兵表示段不存在。

    ★ 4.4：快照语义——构造时拷贝 StableState/MaxOffset/MinOffset/GrowthLimit 四标量， 此后不再更新，不反映段的后续变更（如 Compact 替换 / ReclaimHead 回收）。 长生命周期持有者需重新调 GetSegment/TryGetSegment 取新快照。

    StartupParameters

    段表启动参数——启动期双尾水位的初始设定（SetStartupTails(StartupParameters) 的输入）。

    ★ 只携带水位：生命周期参数（GrowthLimit/分段开关）构造期经 SegmentTableSettings 传入 ——**构造 = 配置，启动 = 双尾**。

    ★ 两个值：同址 = 截断/重置形态；committed < allocated = 扫盘恢复形态（存在已分配未提交尾部）。 单值构造即双尾同址。

    ★ 无持久化启动的显式通道：构造段表 → SetStartupTails(StartupParameters) 定双尾 → 直接 Allocate 运行， LoadAddressTable(IAddressTableReader) 全程可选。

    Interfaces

    IAddressTableReader

    地址表读入委托——对称 IAddressTableWriter，底层调此接口从持久化数据恢复段表。

    IAddressTableWriter

    地址表写入委托——对称 IAddressTableReader，底层调此接口将段表持久化到存储设备。

    ISegmentHandler

    段处理器——段的事件模型接口（AddressSpace 主类实现）。

    ★ SegmentTable 经此接口触发段生命周期事件 + 提交低频后台任务，不直接依赖主类 / LifecycleCoordinator / ISegmentLifecycle——依赖倒置消除反向依赖。

    ★ 主类实现此接口做两件事：① 段生命周期事件适配设备层 ISegmentLifecycle（带优先级队列入队） ② 低频后台任务由 worker 顺序执行。

    ★ 两类回调的区分：

    • 段生命周期事件（OnXXX）：需要设备层（建/满/删/替换物理段），高频，需要优先级
    • 后台任务（SubmitBackgroundWork(Action)）：段表自洽的纯内存工作（如区间表压缩）， 低频，顺序执行不需要优先级

    ★ 单实现 + GDV（Guarded Devirtualization）→ JIT 内联为直接调用，零间接开销。

    ISegmentLifecycle

    段生命周期接口：用于管理段的创建和满时的回调。

    Enums

    StableState

    段生命周期稳态（byte 持久化，按值兼容——Ready 承袭原 Written 的值 1）。

    ★ 两层协议映射（设计文档 lease-protocol-unified-design.md §1.3）：每层恰好一个准入态——

    Empty = 第一阶段（逻辑）准入：地址空间有效，可分配、可占区间；物理门关。

    Ready = 第二阶段（物理）准入：建段完成/恢复在案，chunk IO 合法（WaitSegmentReady 守的就是这道门）。

    ★ "有已提交数据"是导出属性（Ready && MaxOffset > 0），不是稳态—— 池预建段/内存引擎段/恢复段出生即 Ready 且零数据。
