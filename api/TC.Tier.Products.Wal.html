Namespace TC.Tier.Products.Wal

Classes

TierWal

TierWAL——协议中立 WAL 产品（raft/p2p 的存储中线）实现类。

★ 心智模型（设计决策 2026-08-25）：地址是事实——entry 地址只在 Append 返回值记录， 绝不解析/推导逻辑地址结构（重启后段几何可能变，推导即错）；不记录段——段是底层的概念， 上层地址空间无限；index（long）= 顺序值，一条 entry 一个 index 一个地址（单调一一对应）。

★ TierWAL 自己的三段式（每层在自己的槽位定义自己的格式）：

- 头部 = opaque 容器（TC.Tier.Products.Wal.WalOpaqueLayout）：只记 [maxIndex→addr][minIndex→addr] + raft 元数据预留区——搭 Meta 边车随显式提交原子落盘（CRC 完整性由底层 Meta 兜底）

- 数据 = EntryLog 公共方法（Append/OpenCursor/Truncate*/SetOpaqueMeta）——TierWAL 不碰底层帧结构

- 尾部/校验 = 底层 Meta 的原子持久化 + CRC32C（TierWAL 零机制知识）

★ 生命周期 = LifecycleBase<THints> 标准模板（恢复状态机/进度/取消/资源组）—— 恢复核心 = TierWal.TierWalRecovery（RecoveryBase 派生：层间 join EntryLog + opaque 解析 + 统一扫描重建锚点）。

★ 定位（给定 index）：内存稀疏锚点二分（append 时每 TC.Tier.Products.Wal.TierWal.AnchorInterval 条记一个 [index→addr]，零 IO）→ 从锚点地址顺序扫帧（magic 有效帧）数到目标 → 有效停止。 恢复时从头顺序扫一遍重建锚点（= raft 恢复重放本身，不额外成本）。

★ 双水位：AllocatedIndex（内存计数，含攒批窗口）/ PersistedIndex （最后显式提交水位——raft 语义的 last persisted index 可信下限）。

TierWalBuilder

TierWAL 构建者（三段式装配惯例同 StorageEngineBuilder：Options 配置链 → Builder → StartAsync 一步到位——构建 + 恢复 + WaitForReady 一体）。

★ 注入面开放（设计决策：委托注入开放——不注入回落默认，Meta 校验兜底不可绕过）。

★ 启动状态机：只能成功启动一次（重复抛）；失败可重试（销毁重建 EntryLog 实例，对齐 RecoveryBase"Failed 销毁重建"哲学）。

TierWalOptions

TierWAL 配置（不可变 record + With 链——装配惯例同 StorageEngineOptions）。

Structs

WalAppendLease

★ 批追加租约（ref struct——BeginAppendBatch() 产出，using 包裹）： 逐条 Append(ReadOnlySpan<byte>)（返回该条 index，页满 = 底层让渡零阻塞）+ 地址→index 簿记，Dispose 收尾释放。★ 绝不跨 await 持有（持 WAL 写锁——ref struct 编译器强制不逃逸）。

★ 分层：载荷帧格式知识归调用方（适配器）——lease 只收"一帧 payload"，内容零知识。

★ index 簿记宿主权威：index = AllocatedIndex + 1（单写者串行下每条 Append 后 AllocatedIndex = 该条 index）；租约零跨 await 可变状态——背压慢路的收尾在 static 助手 （只传值）内完成，续体线程安全。

WalRecoveryHints

TierWAL 恢复 hints——外部主动注入的已知水位（地址级，同 LogRecoveryHints 语义）。

★ 地址 = 事实：TierWAL 不解析/不推导逻辑地址结构，hints 直接透传底层 EntryLog （恢复优先级统一：① hints ② meta ③ 扫盘——底层模板裁决）。

★ 通常无需提供（default 让底层自恢复）；冷启动已知水位（如进程外归档）时注入。

Interfaces

ITierWal

TierWAL——协议中立 WAL 产品（raft/p2p 的存储中线）。

★ 定位：存储侧把 raft 协议要求的全部持久化语义做齐但内容零知识——entry 内容不解析、 元数据内容不解析（Opaque 槽）；raft/p2p（TC.Tier.Products.Net）是纯消费方，直接接线即可。

★ 能力映射（底层 EntryLog 已实现，TierWAL 只封装 + 自定 opaque 容器布局）：

- 追加：组提交 AppendBatchAsync(IReadOnlyList<ReadOnlyMemory<byte>>, CancellationToken)（raft 攒批）/ 单条 AppendSingleAsync(ReadOnlyMemory<byte>, CancellationToken)

- 显式提交 CommitAsync(CancellationToken)（raft 同步点：一次 fsync = 一批持久化）

- 截断：TruncatePrefixAsync(long, CancellationToken)（头压缩，与写并行）/ TruncateSuffixAsync(long, CancellationToken)（冲突修正）

- 重放 ReadFromAsync(long, CancellationToken)（随机起点顺序读，index 定位 = 段表二分 + 段内扫帧计数）

- 元数据 Opaque 槽 WriteMetaAsync(ReadOnlyMemory<byte>, CancellationToken)/ReadMeta()（term/vote/config 原子替换）

- 快照导出/导入 ExportSnapshotAsync(CancellationToken)/ImportSnapshotAsync(CancellationToken)（一致性点 N₀ 进帧 Header）

★ index 承载（设计 §8.7）：raft 日志连续无空洞——index 由"起点 + 顺序计数"推导， 帧内零 index；段 anchor 表随 opaque 原子落盘（恢复 O(1) 读全表）。

★ 双水位：AllocatedIndex（内存计数，含攒批窗口）/ PersistedIndex （最后显式提交水位——raft 语义的 last persisted index 可信下限，自动提交只提前落盘不推进）。

IWalBatchLease

★ 批读租约（ReadBatchLeaseSync(long, int, CancellationToken) 产出——复制读热路径零分配原语）： Entries = WAL 页缓冲切片的惰性流式视图（底层游标 MoveNext 驱动逐条产出——不预物化）， 仅租约存活期且单次枚举有效（游标前进不可重放）；Dispose 归还页（视图失效）。
