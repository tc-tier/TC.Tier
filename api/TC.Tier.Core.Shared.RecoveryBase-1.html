    Class RecoveryBase<THints>

    ★ 通用恢复模板基类（Core 层）——模板方法模式：钉死 RecoverAsync(THints, CancellationToken) 编排， 子类只 override OnRecoveryCoreAsync(THints, CancellationToken)（真正的恢复算法）。

    与 LifecycleBase<THints> 对称：LifecycleBase 钉死 Initialize 的 前→中→后三阶段，RecoveryBase 钉死 RecoverAsync 的五步编排 （TryEnter → WaitForDependencies → Start → Core → Complete → MarkReady）。两者合起来构成 "生命周期 + 恢复" 的完整通用骨架——继承 LifecycleBase + 注入 RecoveryBase 派生实例即可。

    ★ 消灭各 IRecovery<TRecoveryHints> 实现复制粘贴的状态机样板： CAS 三态闸门 + _state + MarkReady/Reset/RaiseProgress/ TryEnterRecovering + Start/Complete 钩子 + RecoverAsync 编排 + 失败置 Failed——全部收进基类。

    ★ OnRecoveryStart()/OnRecoveryComplete() 由本模板在 RecoverAsync 内 保证调用（串行接在 Core 前后），不再是各实现手动调的"伪钩子"。当前为 public virtual 以满足 IRecovery 接口契约；待接口瘦身（移除这两个方法）后收为 protected virtual。

    CancelRecovery()

    ★ 取消恢复（显式通道）——LifecycleBase.CancelRecovery 调用，通知 IRecovery 实现做取消清理。

    与 CancellationToken 配合：LifecycleBase 同时发 CTS.Cancel()（信号兜底）+ 本方法（显式通知）。 实现可在此停止扫盘、释放扫描持有的资源、记录取消点等——这些只靠 ct 轮询做不到。

    ★ 默认实现为空操作（DIM，仅依赖 ct 轮询）；需要显式取消清理的实现 override 本方法。 对齐 lease Rollback()/ForceRelease() 显式动作范式。

    OnRecoveryCoreAsync(THints, CancellationToken)

    ★ 恢复核心——子类唯一必须 override 的钩子：真正的恢复算法（扫盘 / 读 meta / 回放 / 重建索引 / 装配策略）。

    在 OnRecoveryStart() 之后、OnRecoveryComplete() 之前执行。进度上报用 RaiseProgress(int, string?)（推进 phase/percent/detail）；取消检查用 ct（在 IO checkpoint 处 ct.ThrowIfCancellationRequested()）。

    ★ 四级回退（hints → meta → 引擎水位 → 扫盘）等恢复策略差异，全部封装在此 override 内—— 模板不关心具体算法，只保证 Start/Core/Complete 的串行编排。

    OnRecoveryStart()

    ★ 恢复开始钩子——默认上报 Recovering/0%。由模板保证在 Core 前调用。

    子类可 override 改 detail 文案（如 "engine recovery start"/"index recovery start"）， 一般不需要改起始 phase（统一 Recovering 便于上层进度条聚合）。

    Declaration

    Remarks

    RecoverAsync(THints, CancellationToken)

    ★ 固定编排：CAS 闸门 → WaitForDependenciesAsync(CancellationToken)（层间 join）→ OnRecoveryStart() → OnRecoveryCoreAsync(THints, CancellationToken)（★ 唯一必 override）→ OnRecoveryComplete() → MarkReady()；异常置 Failed。

    ★ 子类不 override 本方法——恢复算法差异通过 override OnRecoveryCoreAsync(THints, CancellationToken) 表达， 层间依赖（等子引擎就绪）通过 override WaitForDependenciesAsync(CancellationToken) 表达。

    ★ 并发语义：已 Ready → 幂等 no-op 返回；Recovering 中 → 抛 InvalidOperationException （恢复不可重入）；Unrecovered → 进入恢复。

    ★ 失败语义（含取消）：异常 → 置 Failed（存 RecoveryState 的 Error，可观测）+ 闸门回 Unrecovered（允许重试）+ 重抛。取消当前并入 Failed——对齐现有各 IRecovery 实现； 子类若需"取消≠失败"的细分，可在 OnRecoveryCoreAsync(THints, CancellationToken) 内自行 catch OperationCanceledException 处理。

    WaitForDependenciesAsync(CancellationToken)

    ★ 层间依赖 join——RecoverAsync(THints, CancellationToken) 在 OnRecoveryStart() 之前调。

    默认 CompletedTask（无依赖，如 Blob/Block）。需要"子引擎先就绪"的持有者 override：在此 await owner._engine.WaitForReadyAsync(ct)（Log/Index/Ring/Metadata 模式）。

    ★ 这是 fire-and-forget Initialize 模型下层间数据依赖的合法表达点：父层恢复核心读子层恢复产物 （如引擎 SectorSize / 段表），故须在 Core 前 join 子层。见 LifecycleBase<THints> 的 "Complete/Ready/恢复完成 三者同义"不变量——join 的正是这个语义。
