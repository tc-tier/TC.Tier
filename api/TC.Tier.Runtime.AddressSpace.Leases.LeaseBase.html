lease 基类——公共机械（占住/多 chunk 协调/doneMask 终态仲裁/Dispose），不含操作类型语义。

★ 每个操作类型是独立的类型化 lease 协议（AppendLease/WriteLease/ ReclaimLease/ReclaimHeadLease/ReclaimTailLease）—— 类型即协议：终态收敛由子类 override FinalizeTerminalCore() 表达，不做 kind 字节路由 （复拆：五合一的单体 OperationLease 抹掉了类型协议边界，上层怎么修都修不干净）。

★ chunk 终态仲裁（doneMask）与 Extents 机械在基类——与操作类型正交。

Methods

Commit()

提交整个 Lease——批量扫尾（对未终态 chunk 执行与部分提交完全相同的操作）+ 终态收敛。

★ 不是第二种原子性：原子单元是 chunk，本方法只是批量（设计文档 §1.2）。

★ TryMarkDone 仲裁：已终态（含并发刚终态）的 chunk 跳过——exactly-once，不重放。

★ 物理门不变量（lease-protocol §1.3）：chunk IO 未执行过的 chunk，扫尾提交前必须先过 EnterChunkPhysicalGate(ExtentLease)（与 chunk 流水线第一拍同一道 Empty→Ready 门）——已 Ready 段 走快路径立即返回，常态（流水线已全部提交）零开销。

EnterChunkPhysicalGate(ExtentLease)

chunk 物理门——类型化协议各自表达对本 chunk 段稳态的要求（调用点：chunk 流水线第一拍 + 整体提交扫尾）。

★ 基类默认无门（Reclaim 系协议：打洞/截断/删段，不等物理就绪）。

★ AppendLease/WriteLease override 为 Empty→Ready 物理门—— Append/Write 全部 chunk IO 与提交都必须等物理段（设计决策：协议要求不可混合进基类）。

FinalizeTerminalCore()

lease 终态收敛——类型化协议钩子：子类路由到段表的本类型 Finalize 方法。

★ 无方向：Append/ReclaimHead/ReclaimTail 的物理操作在 lease 存在时已不可逆， 终态收敛与提交/回滚方向无关。Write/Reclaim 无终态收敛（整体级无段表副作用）——空实现。

★ 幂等：被双触发（部分路径终态 + 整体路径）接近同时调两次也安全—— 推尾 max-CAS / ShrinkHead 条件推进 / ShrinkTail 条件回退均幂等。
