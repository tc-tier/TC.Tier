MagicLocator

IStorageEngine 地址空间的魔术字方向性定位（不透明字节——零/非零全部是有效数据， 无任何格式/布局假设）。

★ 契约（使用方三输入，工具零假设）：只匹配传入的魔术值；方向性（需要最后=地址最大匹配点, 需要最小=地址最小匹配点）；范围由使用方给（格式知识剪小搜索域）；alignment 是扫描步进 速度提示——步进跳过的偏移不检查，使用方必须传自己格式的真实对齐（无对齐保证传 1）。

★ 两步定位协议：本类（引擎侧）按 magic 值扫描做粗锚点——返回精确匹配地址 + 所在页起点； 上层使用者（Log/Ring/Mirror 恢复）从锚点起结合自身格式精确查找记录边界（magic 只提名候选， 结构/CRC 才是裁决）。

★ 扩展方法形态（纯消费面算法——只吃 IStorageEngine 公开面，无引擎内部状态）： engine.Locate(...) 或静态形态 MagicLocator.Locate(engine, ...)。

StorageEngineBuilder

存储引擎构建者（builder.build——设计决策：Options 构建配置 → Builder 构建引擎 → Start 启动引擎一步到位）。

★ 外部使用者的唯一引擎入口：using var builder = options.Builder(fs); var dev = builder.Start(hints) 或 StartAsync(hints)——构建 + Initialize + 就绪等待一体；实现类（StorageEngine）internal 不对外，不允许外部直接调 Initialize（启动统一经本类的 Start/StartAsync）。

★ 启动状态机：Start/StartAsync 只能成功启动一次（重复启动抛 InvalidOperationException）；失败可重试——启动失败销毁重建引擎实例 （对齐 RecoveryBase"Failed 销毁重建"哲学），再次 Start 用新引擎。

★ 装配依赖（compact/checkpoint/logger/hub/epoch）在 Options.Builder(...) 传入—— 构建上下文与配置（Options）分离。

StorageEngineOptimization

存储引擎优化参数——用于调整存储引擎的性能和资源使用策略。

StorageEngineOptions

存储引擎配置构建器（完整 builder 模式，设计决策）——外部使用者的构建链起点： new StorageEngineOptions(...).WithXxx()...Builder(fs).Start()，实现类 internal 不对外。

★ 不可变（record class）：全部属性 init-only，With* 返回新实例（with 表达式）—— 配置对象可安全共享/复用（模板派生变体）、链式无副作用、线程安全。

IStorageEngineFaultInjector

引擎故障注入器（故障注入面补全设计 件二——引擎缝常设对抗面，非测试代码泄漏）。

★ 哲学对齐 spec-12 §9.2 传输面：注入脸只建在真实失败边界上。引擎缝 = 契约级失败 （引擎对上层的合法异常/等待语义）与状态窗；盘的故障类（失败/腐败/慢/乱序）归 fs 脸 （Core.IO FaultInjectingFileSystem），数据伪造（错值/短读）不做——数据破坏是盘的故障类。

★ 挂载：WithFaults() 显式开启（缺省关闭零开销——引擎各公开 op 入口一次空引用短路），经引擎 Faults 属性取得本面。
