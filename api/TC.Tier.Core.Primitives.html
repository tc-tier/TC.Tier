    AsyncCountDown

    异步倒计时器：当计数器从非零降到零时，唤醒所有等待者。

    底层基于 AsyncManualResetEvent（ManualResetValueTaskSourceCore<TResult>）， 常规等待路径零堆分配（传统 TaskCompletionSource<TResult> 方案每次等待有一次堆分配， 且 nextTcs 赋值非原子存在竞态；本实现消除分配并修复竞态）。

    语义：初始/计数归零时事件 set（等待立即返回）；Add() 使计数 > 0， 事件 reset（等待阻塞）。

    AsyncManualResetEvent

    基于 PooledValueTaskSource 的可复用异步手动重置事件。

    语义对标 ManualResetEventSlim，但暴露 ValueTask 异步等待入口，常规等待路径零堆分配。

    多 waiter 广播：Set() 唤醒当前所有等待者；事件保持 set 状态， 后续 WaitAsync(CancellationToken) 立即返回，直到显式 Reset()。

    AsyncOperation

    一次性后台操作的状态句柄（无结果变体）——把"同步线程原地阻塞等异步操作"改造为 「异步信号 + 可轮询状态机」的 Core 原语（docs/sync-async-bridge.md §4，SyncAsyncBridge 消费方）。

    ★ API 与既有 AsyncOperation 全兼容（构造/状态/Report*/Wait*/ThrowIfFailed/Describe）—— 拆基座改造零回归；新增 Progress、Failed、Cancel()、 CancellationToken（后台操作通用契约）。

    ★ 后台操作统一用法：new AsyncOperation(name, logger, externalCancel) → worker 检查 CancellationToken → ReportProgress/ReportSucceeded/ReportFailed。

    AsyncOperationBase

    一次性后台操作状态句柄的机制基座——AsyncOperation / AsyncOperation<TResult> 共用（docs/sync-async-bridge.md §4）。

    ★ 通用后台操作原语（升级）：取代 Storage 层 IReclaimOperation/ICompactOperation 两套同构句柄的手写实现（TCS + 事件 + 时序对齐三层各写一遍）——事件/取消/进度/结果/等待 一套契约一处实现，后台操作统一 new AsyncOperation(...) + Report*。

    ★ 实现 IAsyncOperation（Contracts）——消费面全集见接口（含 AsyncOperationStatus 状态轮询 / IAsyncOperation.Wait(int, CancellationToken) 同步兜底 / ThrowIfFailed() 终态取异常）。

    ★ 三种消费模式：① 轮询 Status/IsCompleted（多消费者安全）； ② WaitAsync(CancellationToken)（异步一等公民，失败/取消重抛）； ③ Wait(int, CancellationToken) （同步兜底——内嵌 AsyncManualResetEvent 的 「自旋 → park 分片」分层等待，全程有界，绝不裸 Task.Wait()）。

    ★ 事件：Progress（进度）+ Failed（失败/取消终态，含订阅者异常隔离）； 成功终态事件由子类经 OnSucceeded() 触发（无结果变体无 Completed 事件——await 等价）。

    ★ 取消：Cancel() 触发内部链接令牌（构造可链接外部取消——引擎 Dispose 自动取消在途操作）； CancellationToken 供后台 worker 在检查点响应。

    ★ 状态机：构造即 Running（可见性原则）；终态经 CAS 单次转移、 不可逆；首个 Report 生效，后续幂等 no-op（对齐 RecoveryBase"Failed 销毁重建"哲学——重试 = 新建操作）。

    ★ 事件时序契约（Storage 历史 flaky 根因区收口）：终态事件先于完成信号置位——等待者 （WaitAsync(CancellationToken) 唤醒）苏醒时事件必已投递；订阅竞态经 IsCompleted 兜底。

    ★ 泄漏绊线：终态 Failed/Canceled 且从未被任何消费模式观察 → 终结器告警（无 logger 静默， 对齐 LifecycleBase 泄漏探测哲学）。

    ★ #if DEBUG：状态转移环形记录（最近 16 次：时间戳/线程/方向）， Describe() 自动携带——对齐 SpinRWLock 值示波器。

    AsyncOperation<TResult>

    一次性后台操作的状态句柄（有结果变体，仿 Task{T}）——后台操作携带结果（如 CompactResult）。

    ★ 用法：new AsyncOperation{TResult}(name, logger, externalCancel) → worker 完成时 ReportSucceeded(result)；消费方 await op.WaitAsync() 拿结果（失败/取消重抛）。

    ★ Completed 事件（携带结果）先于 WaitAsync(CancellationToken) 唤醒（时序契约见基类）。

    Atomic128<T>

    标准 128 位 CAS 单槽封装——16B 对齐背板 + 能力探测降级 + 裸读不撕裂。

    ★ 消除各处（TailWatermarkSlot/IndexBase/AsyncPriorityQueue）重写的 128 CAS 样板：16B 对齐分配 + Unsafe.As<T,Int128> reinterpret + CompareExchange(ref Int128, Int128, Int128) + 能力探测 + lock 降级。

    ★ 统一对齐保证：托管数组（T[]）只保证 8B 对齐，无 16B 对齐保证—— lock cmpxchg16b 要求 16B 对齐，未对齐会 #GP（硬件异常）。本封装用 AlignedMemoryManager（64B 对齐 ⊃ 16B，且独占缓存行避 false sharing）做背板， 从根上消除"碰巧 GC 分配对齐"的定时炸弹。

    ★ 标准用法（参考 TailWatermarkSlot）：CAS 循环 = Read() 裸读当前 → 业务条件检查 → 算新值（含 ABA version）→ TryCompareExchange(T, T) → 失败 SpinWait.SpinOnce() 重试。

    ★ 能力探测 + 降级：native 128-bit CAS 不可用时（生产永不触发）退化到 lock， 行为与 native 路径完全一致（位精确）。测试钩子 _casEnabledForTesting 反射改写触发降级分支 （沿用 TailWatermarkSlot 旧约定）。

    FairGate

    公平门——围绕「重试循环获取资源」的到达顺序协调器。资源本身不属于本门（占用/释放由调用方的 tryAcquire/业务逻辑负责），门只做两件事：让后来者不插队、唤醒并让渡先手。

    ★ 协议（三方角色）：

    获取方 fast path：先查 HasWaiters——有等待者时不走快路径（否则零间隙 复占者永远插队，被唤醒者的调度延迟 > 让渡窗口时持续失手——实测 3/8 残余超时根因）。

    获取方 slow path：TryAcquireSlow(Func<bool>)——登记等待者，持门锁内执行 tryAcquire， 成功返回 true；失败 park 等待唤醒（带超时防丢失唤醒），返回 false 由调用方重试。

    释放方：资源变为可获取后调 Wake()——PulseAll + 让渡 5ms 先手（唤醒者随后的 复占是热自旋 µs 级，刚被唤醒的竞争者若无先手则每次 Pulse 后仍被抢回——实测 4/8 超时残余）。

    ★ 演进自 SegmentTable 手搓公平门（AcquireExtent 双写者长持锁窗口饥饿根治， 7a9685aa），行为保持式下沉——50ms park / 5ms 让渡为当时调优值，常量不做配置项。

    ★ 成本：无等待者时 fast path 仅一次 volatile 读（~1ns），Wake 零阻塞直返；有等待者走 Monitor（µs 级）——用于「临界区外就是 IO」的场景足够，不做队列自旋（无真实调用点）。

    ★ 约束：tryAcquire 在门锁内执行——其中不得再获取与本门逆序的锁（锁序由调用方保证）； tryAcquire 必须纯内存、无异常、快速返回。

    KeyComparer<TKey>

    默认 key 比较器：XxHash64 哈希 + Comparer/EqualityComparer.Default 比较。

    ★ XxHash64 是 .NET 内置高性能非加密哈希（System.IO.Hashing），同款用于上层 HashKV。

    ★ 对 unmanaged TKey 按 SizeOf<T>() 字节做 hash，分布均匀。

    NativeArena

    NativeArena 是一个简单的非托管内存分配器，提供类似竞技场（arena）的内存管理方式。 它在初始化时分配一块固定大小的非托管内存，并允许在该内存块中进行快速的线性分配。适用于需要高性能、低开销的内存分配场景，例如临时缓冲区、批量数据处理等。

    NodeArena

    节点指针竞技场——变长节点的非托管驻留内存分配原语（上层节点形态的基座，如 SkipList arena 化节点）。

    ★ 分块 CAS-bump：4MB 块内 Interlocked 递增分配（读者侧 admit 也安全——无锁快路径）， 块满建新块（lock 下双重检查）。块只增不减、指针恒稳（永不重分配搬移）——缓存进 上层缓存映射表持有的裸节点指针跨块增长长命有效。

    ★ 无释放单语义：块内存生命周期=arena 生命周期（Dispose 全释放）——索引节点缓存不逐出 （节点即数据教义），无需 per-node free。并发 admit 竞争的重复节点=有界字节浪费，非泄漏。

    ★ 单写者+并发读者契约（同索引缓存族）：Alloc 可并发；Dispose 由结构层 Resources 收口 （确定性先于读者终结——读者经索引生命周期闸门保证）。

    PooledValueTaskSource

    池化的单次完成 IValueTaskSource——每次 Rent 一个独立实例， SetResult() / SetException(Exception) 后归还复用。

    多 waiter 广播的正确做法：每个 waiter 持有独立的 PooledValueTaskSource 实例 （而非共享一个 core），由发起方在全部完成时逐个 Set。这与 AsyncManualResetEvent 的共享 core 语义互补：本类型面向"一次性、单消费者"的高频 IO 唤醒场景。

    双层池化（thread-local Stack<T> 热路径 + ConcurrentStack<T> 全局回退 + 批量搬运）， 常规 Rent/Return 往返零争用、零堆分配。

    SectorAlignment

    提供对齐操作的扩展方法，用于将值向上或向下对齐到指定的倍数。默认对齐到 4K 或 2G。

    ★ alignment 必须是 2 的幂且为正——底层位运算 (value + mask) & ~mask 仅对 2 幂成立：传 0 会静默返回 0、传非 2 幂/负数会静默产生错位对齐值，极难排查 （IO 对齐错误会引发 O_DIRECT 失败、数据错位等连锁问题）。

    ★ 入口用 IsPow2(int) 校验（单条 CPU intrinsic，纳秒级，分支预测下几乎零开销）+ Utilities.ThrowHelper（[DoesNotReturn] + NoInlining）隔离冷 throw 路径， 热路径内联不受影响。

    SpinRWLock

    写偏向自旋读写锁——单 64 位字 CAS，读共享 / 写排他，等待中的写者挡住新读者（写不饿死）。

    ★ 64-bit 位布局：bit63=写持有，bit62=写等待（pending），bits61..32=读计数，bits31..0 保留。

    ★ 写偏向协议：写者进门即置 pending，读者 fast path 检查 Writer|Pending 任一置位即退避—— 写者最多等「在途读者」退出，不被持续读者流饿死。读者 fast path 仍是一次 CAS。

    ★ 临界区约束：排他临界区必须短（纯内存、禁 await——Debug 释放线程校验会抓）；共享可长持/跨 await （计数语义无线程亲和，读计划锁跨 IO 持有是合法用法）。跨 await 持有越久，写者与被挡读者等待越久。

    ★ 演进自 LockWord（终态替代，读优先→写偏向；Monitor Wait/PulseAll 职责删除——生产零调用）。

    ThrowHelper

    ThrowHelper 用于集中处理异常抛出，避免在调用点重复编写 throw 语句，提高代码可读性和维护性。

    UnifiedCrc

    统一 CRC 计算工具——全部类型共用（unified-binary-layout.md §2 FLAG_CRC32C / FLAG_CRC64）。

    CRC32C（Castagnoli 0x1EDC6F41）：硬件加速。x86 走 Sse42.Crc32（每 cycle 8B）， ARM 走 Crc32.ComputeCrc32C。用于 DeltaLog / FixedBlock / PageMirror / Meta。

    CRC64（ECMA-92）：软件实现。用于 EntryLog / StreamBlock / IndexMirror 常驻文件抗位衰减。

    ★ 线程局部复用 Crc64 实例，避免热路径 GC 压力。CRC32C 走内建指令无对象分配。

    Utility

    通用工具类。提供字节大小解析、2 的幂运算、哈希计算、单调更新、blittable 判定等通用工具方法。

    Structs

    MicroTimer

    微秒计时器 —— 封装 GetTimestamp() 的零分配计时。

    ★ 零分配：readonly struct，栈上分配，无GC压力。

    ★ 采样门控：active=false 时完全零开销，JIT自动消除计时逻辑。

    ★ 整数换算：全程无浮点运算，全量程无精度损失。

    使用方式：

    var s = MicroTimer.Start(_hub.Wal.ShouldSampleAppend());
// ... 执行业务逻辑 ...
if (s.IsActive) _hub.Wal.OnAppend(s.ElapsedMicros(), entry.Length);

    MonitorScope

    MonitorScope——using 块自动获取/释放 Monitor（与 SpinLockScope 同构的 RAII 面板，锁对象版）。

    ★ 取代 no-tracking SpinLock 的场景（挂起取证定案）：SpinLock 的 复合锁字（持锁位 | 等待计数 | 跟踪禁用位）在 Sleep 型重竞争交错下可被孤立——实测 dump 中 _owner=0x80000003（持锁+1 登记等待者）而全进程零持有线程，等待者 Sleep(1) 循环永等 持锁位清零（ConcurrentReadWrite WriteThrough 挂起 60s+，fsync 0.1ms 洗清磁盘延迟）。 Monitor：owner 跟踪健壮 + 竞争者 futex park（内核精确唤醒）+ 无外部可腐蚀状态。

    ★ 契约：Enter/Exit 同线程配对（临界区内不跨 await/线程交接）；可重入（Monitor 语义）。 零分配（ref struct + 装箱过的锁对象由持有方常驻）。

    ★ C# 12 兼容：ref struct 不实现 IDisposable（C# 13），pattern-based using。

    SpinLockScope

    SpinLockScope——using 块自动获取/释放 SpinLock（避免忘记释放锁）。

    ★ C# 12 兼容：ref struct 不实现 IDisposable（ref struct interfaces 是 C# 13）， 靠 pattern-based using 自动调用公开的 Dispose()。

    SpinRWLock.ExclusiveScope

    排他锁 scope——using 自动释放。构造时 AcquireExclusive，Dispose 时 ReleaseExclusive。

    SpinRWLock.SharedScope

    共享锁 scope——using 自动释放。构造时 AcquireShared，Dispose 时 ReleaseShared。

    IKeyComparer<TKey>

    索引 key 比较器 + 64 位哈希抽象（公共，跨结构）。

    ★ 对齐 base.md §2.8「统一 IKeyComparer 比较器 + 哈希函数抽象」。

    ★ 64 位 hash 是性能命脉：高位取 tag（14 位，熵充分），低位取 bucket index，两段独立。

    ★ 默认实现 KeyComparer<TKey>：XxHash64 over TKey 字节（unmanaged，blittable）。

    ★ 可注入：自定义 key 类型可提供专用比较器（如变长 key 的前缀哈希、特定分布优化）。
