    Classes

    CopyMetadata

    拷贝元数据指令——null（不传本类型）= 复制源元数据（S3 CopyObject 默认）； 非 null = 以 Metadata 替换目标元数据。

    MultipartUploadSession

    进行中的 multipart 会话描述（孤儿判定基准——会话治理原语的返回件）。

    ObjectInfo

    对象元数据探测结果（HeadObject 语义归一）。

    ObjectKeyValidator

    对象键共享校验规则（契约冻结项 §9.5——桥与实现同一实现）。

    ObjectMetadata

    对象用户元数据——"PUT 时原子快照，非实时可变元数据"（对象间不可变；上限归一 2KB——全厂商最严约束）。

    ★ 超限/非法键直接抛 ArgumentException，不静默截断（EngineMeta 类关键元数据 被截 = 恢复失败；数据损坏不可静默——评审中 3/M2 定案）。构造时即校验（早失败——不在 Flush 的 PUT 才失败）。

    ★ 键字符集 [A-Za-z0-9_.-]（RFC 7230 token 最严交集；不转义——转义引入往返不对称，静默转义比拒绝更危险）。

    ObjectStoreExtensions

    同步便捷包装（低频路径专用——高频路径直用异步族）。

    ★ 内部经 SyncAsyncBridge（独立池 + 有界等待）桥接，替代裸 GetAwaiter().GetResult()——推进不依赖公共池、等待有界（超时抛 TimeoutException 带现场）。 详见 docs/sync-async-bridge.md §9 P1。

    RemoteFileSystem

    远程文件系统——IFileSystem 第三介质桥（B3.3/B3.4）：注入的 IObjectStore 升格为文件语义（staging 写回层 / 延迟加载 / multipart 编排 / fencing 卷锁）。

    ★ 构造：Create(IObjectStore, RemoteFileSystemOptions?, ILogger?)——store 注入 （S3ObjectStore / MemoryObjectStore / 任意实现），桥对厂商零知识。

    ★ 键模型：对象键 = {KeyPrefix}{path}（多引擎共桶隔离）；path 经 TC.Tier.Core.IO.Shared.PathValidator （三介质同一实现——越出前缀即 ArgumentException，不可能访问同桶其他前缀对象）。

    ★ Dispose 契约（磁盘方向）："离开目录"——Dispose 后 Open 抛 ObjectDisposedException； 已开句柄继续可用（staging 自持——远程数据在云端不在 fs 内存）；store 归调用方所有不代释放。

    ★ AcquireExclusive = 尽力型 fencing（lock 对象 + 条件 PUT；仅防意外双开，不构成正确性保证—— 时钟漂移可致提前抢锁、崩溃后保护真空 = 心跳超时窗口；引擎正确性由段表 lease 单写者协议承担）。

    RemoteFileSystemOptions

    RemoteFileSystem 桥配置——staging/编排/缓存/隔离的全部数值旋钮（调参事实源，io.md 调参指南对应）。

    ★ 默认值面向"段级对象"负载（日志段 8MB~1GB 量级）；S3 物理约束： PartSize ∈ [5MB, 5GB]、总 part 数 ≤ MaxParts（S3 上限 10000）。

    RemoteSpill

    staging 超限 spill 位置（G7 收编——medium-protocol-and-parity-design §5.7）： SpillDirectory（磁盘路径）+ SpillToMemory（布尔）互斥二态 → 单一概念两形态。

    ★ 形态：磁盘目录（ToDisk(string)，per-fs 子目录自举）/ 内存私有卷（ToMemory()， 嵌入式无盘部署）；null = 不配置（超限 DiskFull 既有语义）。

    ★ spec 对应：spill=local:///var/tmp / spill=memory:（工厂构建器翻译岗）。

    ObjectEntry

    ObjectListing

    分隔符列举结果（IObjectStore.ListDelimitedAsync 返回）——对象（未截断整键）+ 公共前缀（截断聚合：prefix 起至首个 delimiter 含分隔符整段、去重、Ordinal 有序）。

    PutCondition

    PUT 条件前置（对象层条件写底座——fencing 锁的实现原语）。

    ★ 语义对齐 S3 If-Match / If-None-Match：与实现当前状态失配 → FileIOException (PreconditionFailed)，对象不被修改。

    值语义：ETag 或 "*"（任意）。IfNoneMatch = "*" 表"对象必须不存在"（抢建）。

    UploadPartResult

    Interfaces

    IMultipartUpload

    multipart 上传会话——桥层按 part 粒度编排、厂商映射在适配器内（§4.4）。

    ★ 禁止跳 part：对象 = 各 part 顺序拼接的连续字节流，跳过中段 part = 对象缩短 + 偏移整体错位（正确性级错误）——桥全量上传（含全零 part）。

    ★ 碎片回收契约：未 Complete/Abort 的会话（崩溃/异常路径）由桥登记回收（AbortAsync）； DisposeAsync ≡ AbortAsync（异常安全兜底）。

    IObjectStore

    对象存储开放契约——远程对象介质的厂商中立抽象（S3 事实标准为通用货币）。

    ★ Core 只定义契约；实现注入：TC.Tier.Core.IO.S3（SigV4 自写，覆盖 S3/OSS/MinIO/R2/B2 等 S3 兼容云）/ TC.Tier.Core.IO.Testing.MemoryObjectStore（内存替身）/ 任意第三方实现。

    ★ 接口风格 = 异步族为主实现路径（HttpClient 本质异步——同步全量阻塞等待会线程池饥饿）； 同步便捷包装见 ObjectStoreExtensions（低频路径专用）。

    ★ 对象键编码（契约冻结项，§9.5）：UTF-8 / 键长 ≤1024 字节（S3 上限，超限抛错）/ 禁 '\0' 与 CR/LF（破坏签名 canonical request）；统一经 ObjectKeyValidator 校验。

    ★ 错误出口：FileIOException（Core/IO 唯一异常类型）；键不存在 = NotFound； 条件失配 = PreconditionFailed；能力缺失路径 = Unsupported。

    ★ GetAsync EOF 语义（对齐 IFileHandle.Read 的 pread-EOF 契约）：offset ≥ 对象长度 → 返回 0 （S3 416 RangeNotSatisfiable 映射为 0，不抛）——桥层 Read 直通无特判。

    Enums

    ObjectStoreCapabilities

    对象存储能力协商位——IObjectStore 实现的介质异构显式表达（构造时一次性声明/探测）。

    ★ 契约纪律（对齐 FileSystemCapabilities）：每个能力位对应的操作在未置位的实现上有 文档化回退（如 ServerSideCopy 缺 → 下载重传）或抛 Unsupported； 缺 ConditionalPut → fencing 锁降级（remote-storage-s3 设计 §4.6/§6）。

    ★ 表面 = S3 六件套语义超集，不加任何厂商专有方法——专有能力走能力位 + 消费者自决， 永不出现在接口上（§5 设计纪律）。
