QueueGroupState

组状态（tc-tier-queue-spec §5.2 P2 面）定长 codec。

布局（小端，"TQGRP03\0"）： [Magic 8B][Cursor 16B][SkipCount 4B][RetryCount 4B] [Skip[i] 16B × MaxInFlight][Retry[i] 20B（addr 16B + count 4B）× MaxInFlight] [Epoch 8B][Flags 4B]。 Cursor = 连续已确认前缀的下一地址（Invalid = 从未确认）；Skip = 乱序 ack 空洞（升序）； Retry = 活跃重试计数（>0 者——死信判据 redeliveryCount > MaxRedeliveries）； Epoch = fencing 组代次；Flags bit0 = Fenced（EvictOldest 淘汰）。

LogicalAddress 序列化 16B（SegId+Ext+Offset）——地址是事实，不解析结构。 P0/P1 魔数无部署存量——v3 不做兼容（beta 格式迭代期）。

TierQueue

TierQueue——本地持久队列（tc-tier-queue-spec：P0 核心流 + P1 消费组全量）。

★ 组合配方（Ring 骨架）：RingOfQueueKey（数据真相源）+ 组注册表 VersionedMetadata （{name}.groups——组名 + 定格配置）+ 每组一个 VersionedMetadata（{name}.group.{g}——位点/代次 原子提交域）。组 = 独立持久位点 + 独立投递簿记（pending 纯内存）。

★ 治理（spec §8.2 定案①）：Enqueue 前积压检查（MaxBacklogBytes）——Block（默认，有界等待）/ Reject / EvictOldest（fence 最慢组，显式 ResetGroupAsync 续命）。

★ 队列级 P0 兼容面（DequeueAsync/AckAsync/GroupCursor）委托 "$default" 组——地址档基线语义 （无 token 无 fencing）；token 档（fencing/deliver-once）经 CreateConsumerAsync(string)。

★ 线程模型：多生产者并发（Ring tail 串行）；组内 Dequeue/Ack/Claim 经组 _gate 串行；组间并行。

★ 复制面（tierqueue-replicated-spec §8）：显式实现 ITierQueueReplicationPort （不出现在公共面——复制状态机经端口驱动确定性核心；端口方法串行调用契约，apply 管道单 worker 满足）。

TierQueueBuilder

TierQueue 构建者（tc-tier-queue-spec §3.1——三段式装配惯例同 TierWalBuilder： Options 配置链 → Builder → StartAsync 一步到位）。

★ 组合设计思想（注入优先、回落默认）：零件规格全在 TierQueueOptions； 可替换件全走 With\* 注入——Ring 工厂（自定义恢复/游标/快照/meta 策略经生成封闭类全参 ctor 自行装配）、 ring meta 策略工厂、组 meta 工厂、共享 epoch（多结构同域惯例）、logger；不注入 = 内部默认实现。

★ 组是运行时实体（CreateGroupAsync）不经 Builder——P0 单内建组 "$default" 随启动自动就绪。

★ 启动状态机同 TierWalBuilder：只能成功启动一次（重复抛）；失败可重试（销毁重建， 对齐 RecoveryBase "Failed 销毁重建" 哲学）。

TierQueueConsumer

消费组句柄（tc-tier-queue-spec §3 ITierQueueConsumer）——一个组一个消费端实例 （多消费者 = 多句柄同组；ClaimAsync 抢占改派）。组本体归 TierQueue 宿主，句柄 Dispose 轻量。

TierQueueOptions

Interfaces

ITierQueue

TierQueue——本地持久队列（tc-tier-queue-spec）。

★ P0 核心流：Enqueue（append-only）/ Dequeue（游标拉取）/ Ack（位点原子推进 + 截断）/ Flush / Truncate。队列级面委托内建组 "$default"——地址档基线语义（at-least-once，无 token）。

★ P1 消费组：CreateGroupAsync(GroupOptions, CancellationToken)（独立位点/独立投递簿记/定格配置）+ CreateConsumerAsync(string)（token 档——fencing/deliver-once）+ 治理三模式 + GetStatsAsync(CancellationToken)。

★ 交付语义（spec §5/§6.0）：at-least-once——崩溃后从持久位点重放；业务消费须幂等。

★ 分配与持久化分离（同 TierWal 惯例）：Enqueue 返回 = 已入内存；落盘由 AckAsync （契约：ack 数据先于位点持久）或显式 FlushAsync(CancellationToken) 触发。

ITierQueueConsumer

消费组句柄公开面（spec §3——token 档消费：fencing/deliver-once）。

ITierQueueReplicationPort

TierQueue 复制 apply 端口（tierqueue-replicated-spec §8 定案——Products 显式公开端口， 复制状态机经端口驱动写路径/组游标，避免 InternalsVisibleTo 蔓延）。

★ 全部方法 = 确定性核心：同一命令序列在任一副本上产生同一状态（地址分配 = apply 序 ——Ring 尾分配串行；判定依据全部取自命令载荷或已复制状态，禁止本地时钟/本地水位参与判定）。

★ 生命周期：由已就绪的 TierQueue 实现（显式接口实现——不出现在公共面）； 调用方须保证单线程串行（raft apply 管道单 worker 契约）。
