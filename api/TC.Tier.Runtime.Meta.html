Classes

DisabledMetaPolicy<THeader, TPayload>

Disabled meta 策略——no-op（不持久化 meta）。默认值。

所有读写/提交操作都是 no-op；Load 返回 false（无 meta）。适用于无数据/空盘/外部管 hints 场景。

ManagedMetaPolicy<THeader, TPayload>

Managed meta 策略——独立 IStorageEngine + 四段自描述块 + Magic/CRC 校验。

★ 统一布局：[统一 Header N B][内部水位线（结构化）][外部 opaque（实际用量）][统一 Footer CRC 4B]。

★ 自描述核心（设计决策 ）：header.PayloadLength = 水位字节数 + opaque 实际用量； 水线位置 = HeaderSize（固定）；opaque 范围 = 其后至 PayloadLength；footer 位 = HeaderSize + PayloadLength。 容量（可变的启动配置）零参与盘上几何——跨重启容量随便调，读侧全按盘上自述定位，水位无条件恢复。

★ 容量（MetaOpaqueBytes）只做写侧约束：opaque 写入上限 + 缓冲分配 + 引擎段几何。

★ CRC32C 覆盖 Header + 水位 + 实际 opaque（到 footer 前），存于 Footer。

MetadataMetaTransport

外部 meta 介质适配器——把 meta 块托管到 VersionedMetadata（版本链稳定存储）。

★ 3a（外部隔离）语义的推荐实现（设计决策）：需要外部独有 meta 存储时，不再自写 单槽文件/KV——独自写盘要自己解决 torn write 原子性、落盘顺序（data 先 meta 后）、 崩溃恢复一致性，还得自搭 2PC 提交链路。托管到 VersionedMetadata 后：

- 每次写块 = 版本链追加新版本（写到一半崩 = 旧版本完好，CRC/magic 断链天然容错）；

- 持久化点即 WriteBlock(ReadOnlySpan<byte>)（Write + Persist + flush）——对齐 TransportMetaPolicy.Commit 的 meta fsync 语义（调用链保证 data 先落盘）；

- N=2 轮转自动回收（每次写后 ReclaimOldVersions()），空间有界；

- 读 = 内存工作副本零 IO；需要跨结构原子提交时底层已实现 ITransactionParticipant（ 经 Storage 注册进 TransactionLog）。

配置约束：PayloadSize 必须 ≥ meta 块上界 （12B 头 + 水位 struct + MetaOpaqueBytes + 4B 尾）；超限写抛 ArgumentException （fail-fast，不静默截断）。引擎名须与主结构不同（如 "xxx.meta"）。

TransportMetaPolicy<THeader, TPayload>

Transport meta 策略——经 IMetaTransport 写块/读最后一条。

★ 统一布局：[Header N B][Payload 结构化水位 + opaque 扩展][Crc32Footer 4B]—— 块格式与完整性校验完全在策略内，传输只搬字节（单槽覆盖/主流追加/远程皆可）。

★ 变长块：Commit 只写 Header + 实际 PayloadLength + Footer（无 4K 填充——嵌入主流时 不污染数据流）；读写走 4K 对齐的就地缓冲。

★ 契约：未 Load 读返回 null/Empty；Commit 后同实例可读；重新 Load 全量重置； Load false = 空/无数据/校验失败（不区分）；Dispose 幂等。
