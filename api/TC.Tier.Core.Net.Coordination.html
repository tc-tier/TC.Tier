HybridLogicClock

混合逻辑时钟（二期-G1 NETGAP-024——HLC 原语，Kulkarni et al. §3 构造）：

★ Tick（本地事件）：墙钟前进 → 物理跟钟、逻辑清零；墙钟停滞/回拨 → 逻辑 +1 （时间戳永不回退——墙钟回拨被逻辑域吸收）。

★ Receive（收到远端时间戳）：物理 = max(本端墙钟, 本端物理, 远端物理)；三方等物理时 逻辑 = max(本端逻辑, 远端逻辑) + 1——因果吸收（远端领先即跟钟，跨分区重连后时序连续）。

★ 墙钟源可注入（构造参数 wallNow——测试时钟回拨/跳跃场景）。

LockStateMachine

锁状态机（二期-G4——raft 复制的锁表）：ApplyAsync 按序应用 Acquire/Release——

★ fencing token = 命令的 raft applied index：单调（raft 日志序）、跨重启单调（日志持久化）、 可校验（受保护资源比对 token 排除旧 epoch 持有者写入）。

★ 租约 = apply 节点时钟的到期判定（时钟偏移影响租期精度；安全性由 fencing token 保证）。

RaftDecisionInjector

跨组事务决策注入器（二期-G3——NETGAP-026）：把 raft 组共识接到复制事务的 决策注入位（TierSession.CommitReplicatedAsync 的 awaitDecision——Phase 4 对接）。

★ 决策 = 协调组上的一条共识命令（[Kind 1B][TxSeq 8B][CtxLen 4B][Ctx]）： 经 ReplicateAsync(ReadOnlyMemory<byte>, CancellationToken)（applied 档——多数派落盘且本机已应用） 返回即决策定案，decider 返回 true，Confirm-all（不可回退点）随之推进；换届/取消 原样上抛——回滚路径归事务管线（Abort 已 Prepare 者）。

★ 原子性锚点：参与效果在协调组 ApplyAsync(long, ReadOnlyMemory<byte>, CancellationToken) 回调内 随决策可见性落（决策 applied 即效果可复制）——决策未见，效果不存在。

★ 零依赖装配：decider 为纯 BCL 委托形态，本类型不引用事务运行时——由装配层 把两者接上（TierSession 所在工程不反向引用 Core.Net）。
