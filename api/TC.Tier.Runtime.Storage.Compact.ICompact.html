Compact 整理子系统——把散落/有空洞的段搬迁到紧凑新段，回收旧段。

★ 只依赖契约对象：CompactLease（含 Chunks——每段带旧段信息）+ IFileHandle（IO 子系统）。不认识 SegmentTable、不认识 TC.Tier.Runtime.Storage.StorageEngine——搬迁所需信息全在 lease 中，无需穿透查段表。

★ 一律后台句柄形态：Compact(params CompactLease[]) / RangeCompact 返回 IAsyncOperation<TResult>——0 等待；等待/取消/超时由调用方控制 （await op.WaitAsync(ct) / op.Cancel() / 事件订阅）。

★ 失败现场保留 + marker 续传：Phase 2 失败保留（marker + 临时文件）； Recover(CompactLeaseFactory)（启动恢复）/ Retry(CompactLeaseFactory)（运行时续传）从 marker 补执行 promote + 段表替换 + 删 marker——零重拷贝。

RangeCompact(CompactLease, LogicalAddress, LogicalAddress, IReadOnlyList<LogicalAddress>)

启动区间 Compact（带地址翻译的磁盘碎片整理）——把 [from,to) 内的有效数据压实， 消除碎片间隙，压实区末尾到 to 之间 PunchHole 归还（连续空洞）。

★ addresses 是上层需翻译的地址集合——每个不同的请求地址都进入 MigrationMap；allocated 地址映射到新地址，hole/不存在/区间外地址映射到 null。

★ 区间外（from 前、to 后）数据原位不动；CommittedTail 不退。

Retry(CompactLeaseFactory)

运行时失败续传——从 marker 补执行上次失败的 Compact（与 Recover(CompactLeaseFactory) 同核心， 零重拷贝）。区别仅在触发时机：Recover = 启动恢复；Retry = 同进程内运行时失败 （引擎 op.Failed 分流，句柄冲突关句柄后调用）。

★ marker 不存在（Phase 1 失败已清理现场）= no-op，调用方重新发起 Compact。
