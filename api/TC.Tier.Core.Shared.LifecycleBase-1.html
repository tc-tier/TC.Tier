    Class LifecycleBase<THints>

    通用生命周期骨架基类（Core 层）。数据结构基类与 IO 引擎基类共同继承本类，获得统一的

    ★ 实现 ILifecycle<THints>——统一"同步 void Initialize 启动后台恢复 + 观测/等待"模型， 详见 src/TC.Tier.Core/docs/lifecycle.md。★ Initialize 是类面方法（不在 ILifecycle 接口面）—— 设计决策接口面消除：启动入口由各持有者自己的装配面提供（引擎 = StorageEngineBuilder.Start）， 接口只保留观测/等待；结构层内部组合面仍经具体类型调用。

    ★ 内建 Resources（ResourceGroup）——统一资源释放， 子类构造期/钩子里 Resources.Add(...)，Dispose 自动统一转发（消灭各基类 _owner/_disposables 样板）。

    ★ Initialize 是固定模板（IO 引擎与数据结构共用同一套 On 钩子模式）： CAS 闸门 → OnInitializeBegin() → CreateRecovery() → 订阅进度事件 → 后台恢复 task。 子类只 override 钩子，不改流程。

    CancelRecovery()

    取消恢复（向内部后台恢复发取消信号，不保证立即停止）。

    后台恢复在下一个 checkpoint 检查取消令牌并抛 OperationCanceledException。

    ★ 契约：WaitForReady() / WaitForReadyAsync(CancellationToken) / WaitForReady(int) 在取消恢复时会抛 OperationCanceledException（取消=等待被中断）。

    public void CancelRecovery()
    Remarks

    ★ 双通道取消：① CancelRecovery() 显式通知（实现做取消清理） + ② _recoveryCts.Cancel() 信号兜底（RecoverAsync 在 checkpoint 检查 ct 收 OCE）。 两者配合——显式通知覆盖"ct 轮询做不到"的清理（停扫盘/释放扫描资源），信号兜底覆盖长循环。

    子类配置内建 worker——在 OnInitializeBegin() 或 OnInitializeComplete() 里调均可。

    ★ 传入自定义 BackgroundWorkerLoop 派生实例（填了 RunOneCycleAsync/ProcessItemAsync 业务逻辑）。

    ~LifecycleBase()

    ★ 轻量终结器——仅泄漏告警，不释放资源（资源释放走 Dispose；finalize 顺序不可控，不在此做）。

    对齐 lease 防御：实例被 GC 但未 Dispose → logger 告警（无 logger 静默，不冒充）。 这是 .NET 推荐的 finalize 用法（探测泄漏，非释放资源）。

    finalize 队列负担可接受（LifecycleBase 实例数有限，非热路径对象）。

    ⚠️ Logger 是普通引用——终结器运行时实例字段可能已被 GC 回收（finalize 顺序不可控）。 若 Logger 已被 finalize，调用它会抛——终结器抛异常会终止进程。故必须先 null 判断防护。

    Initialize(THints)

    ★ 统一就绪入口（同步 void，启动内部后台恢复后立即返回）。模板方法，子类不改流程、只 override 钩子。

    ★ 类面方法，不在 ILifecycle 接口面（决策）——外部禁止经接口调 Initialize； 引擎侧经 StorageEngineBuilder.Start/StartAsync 一步到位，结构层经具体类型内部调用。

    流程：CAS 幂等闸门 → OnInitializeBegin()（引擎 init + 资源/策略装配） → CreateRecovery() → 订阅进度事件 → 后台 task 跑 Recover → Completed/FAILED。

    ★ CreateRecovery() 返回 null 时跳过后台恢复、直接置 Ready（无需恢复的结构场景）。

    调用线程不阻塞、其他结构不阻塞；只阻塞本结构读写（Ready 前 EnsureReady 抛异常）。

    ★ 重试契约：① 启动阶段失败（OnInitializeBegin()/钩子/CreateRecovery() 抛） 回退 _initialized=0，允许重新 Initialize 重试；② 后台恢复执行阶段失败 （RecoverAsync 抛异常→Failed）_initialized 保持 1，实例不可修复，必须 Dispose 销毁重建 （存储场景 Failed 多为持久数据损坏，重试无意义）。再次 Initialize 会被 CAS 静默拒绝。

    ★ 重试时旧 task 守卫：取消后旧后台 task 可能尚未执行完 catch 块（写 NotStarted/_initialized=0）。 若不等其结束就启动新 Initialize，旧 task 延迟写入会覆盖新状态→状态机崩溃。 故重试路径（存在旧 _recoverTask）必须等旧 task 彻底结束再继续。首次 Initialize 无旧 task，不阻塞。

    OnInitializeBegin()

    ★ Initialize 第一阶段钩子——this 构造完后、后台恢复启动前。

            <p>子类在此：① <code>_engine.Initialize(...)</code>（Runtime 层引擎 init）
          ② <code>Resources.Add(_engine)</code>（注册主引擎到资源组）
          ③ 创建 MetaPolicy（按 MetaPolicyKind）
          ④ 后期资源 <code>Resources.Add(metaEngine/overflowEngine, ...)</code></p>
        <p>此时 this 已完全构造，虚方法安全；<xref href="TC.Tier.Core.Shared.LifecycleBase%601.CreateRecovery" data-throw-if-not-resolved="false"></xref> 紧随其后被基类调用。</p>

    OnInitializeComplete()

    ★ Initialize 第二阶段（[后]）钩子——仅在本实例恢复成功完成后调用。

            <p>★ 不变量：Complete / Ready / 恢复完成 三者同义。每层都用同一 <xref href="TC.Tier.Core.Shared.LifecycleBase%601" data-throw-if-not-resolved="false"></xref>，
          故任意嵌套层此不变量都成立——父层在此钩子里可安全读"本层恢复产物"。</p>
        <p>★ 执行线程：有恢复时在后台 LongRunning task 内（串行接在 <code>await RecoverAsync</code> 之后）；
          无恢复（<xref href="TC.Tier.Core.Shared.LifecycleBase%601.CreateRecovery" data-throw-if-not-resolved="false"></xref> 返回 null）时在调用线程同步执行。</p>
        <p>★ 异常策略：恢复已 MarkReady、实例可用——钩子内抛异常只 log，不 fault 主 task。</p>
        <p>★ 需配 <xref href="TC.Tier.Core.Shared.BackgroundWorkerLoop" data-throw-if-not-resolved="false"></xref> 的子类：在 <xref href="TC.Tier.Core.Shared.LifecycleBase%601.OnInitializeBegin" data-throw-if-not-resolved="false"></xref> 或本钩子里调
          <xref href="TC.Tier.Core.Shared.LifecycleBase%601.ConfigureBackgroundWorker(TC.Tier.Core.Shared.BackgroundWorkerLoop)" data-throw-if-not-resolved="false"></xref> 均可——worker.Start 在本钩子<b>之后</b>跑（等恢复完成 + 装配就绪）。</p>

    WaitForReady()

    同步等待恢复完成（内部 join 后台恢复 task，阻塞当前调用线程直到 Ready）。

    ★ 与 Initialize 的关系：Initialize 启动后台恢复后立即返回； 调用方若需"启动后立即阻塞等就绪"，在 Initialize 后调本方法。

    ★ 不阻塞其他数据结构，只阻塞调用本方法的线程。

    ★ 若恢复已失败（Failed），本方法重抛恢复异常。

    ⚠️ 禁止在异步上下文调用：UI/ASP.NET 等同步上下文下，同步阻塞后台 Task 会经典死锁。 异步调用方请用 WaitForReadyAsync(CancellationToken)。

    Declaration
    public void WaitForReady()
    Remarks

    ⚠️ 禁止在异步上下文调用：UI/ASP.NET 等同步上下文下，同步阻塞后台 Task 会经典死锁。异步调用方用 WaitForReadyAsync(CancellationToken)。
