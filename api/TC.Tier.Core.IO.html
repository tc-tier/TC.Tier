    Namespace TC.Tier.Core.IO

    Classes

    DirectIo

    DIO（无缓冲直接 IO）的缓冲对齐地板——预分配对齐内存（页池/帧池）与句柄校验共用的单真相。

    ★ 与 TC.Tier.Core.IO.Disk.DiskFileHandle 的 _requiredAlignment 同式： Windows = max(扇区, SystemPageSize)（Win DIO 缓冲地址须系统页对齐）； Linux = 扇区（O_DIRECT 逻辑块粒度）。

    ★ 消费纪律：凡打算作为 DIO 写/读缓冲的长命内存（Ring 页池/Log 帧池）， 租用对齐必须取本地板而非卷扇区——按扇区租用令 Windows 下缓冲地址 7/8 概率失配 （卷扇区 512 时），DIO flush 随机抛 FileIOException 对齐错。

    FileHandlePool

    句柄池——IFileHandle 的键控共享缓存（公开原语；三步获取/败者自毁语义搬迁自 StorageEngineBase.FileHandle，第九轮评审重立为 Acquire/Release 协议）。

    ★ 单获取接口 Acquire(string, FileOpenOptions)：读写分离由 options 参数分桶（key 含 Access）； 预分配是创建期意图不进 key——同文件不同预分配大小的两次 Acquire 命中同一实例。

    ★ 归还协议（挂载式，零分配）：池内句柄 Dispose = 归还使用权（默认不关闭底层）； 底层关闭只有三条池内出口——Release(IFileHandle, bool)(close:true)（定向）、 RemoveAll(Predicate<string>)(谓词批量)、Dispose()（全量）。外部任何 Dispose 都不可能关闭池内资源。

    ★ 安全 LRU：maxCapacity 超容只淘汰 idle（usage==0）句柄；in-use 跳过并告警 （"淘汰正在使用的句柄是调用方错误"从文档警告升级为机制保证）。LRU 淘汰不回收派生 IMappedSection（映射生命周期独立）。

    ★ 关闭顺序契约：pool.Dispose 先于 fs.Dispose；Dispose 时 usage>0 告警（忘还观测点）。

    ★ io.md 陷阱：无 maxCapacity 时禁无界增长——长期运行消费者必须周期 RemoveAll 回收。

    FileIOException

    Core/IO 唯一的 IO 异常类型（家族 A·物理层标准）——所有介质实现（磁盘/内存/故障注入）的失败统一出口。

    ★ 铁律：不携带任何存储语义（逻辑地址 / lease / 存储层词汇）——存储语义由消费方在边界包装补充。

    ★ 派生自 IOException（BCL）——消费者可用单一 catch (IOException) 兜底。

    FileOpenOptions

    文件打开语义——Access × Mode × Sharing × Hints 四要素 + 预分配，一次表达完整打开意图 （BCL File.Open(path, FileMode, FileAccess, FileShare) 三要素一一对应，无损表达）。

    ★ 值相等（sealed record，全部成员含 PreallocateSize 参与）——供消费者比较/测试便利； 池缓存的 key 正确性另由专用 HandleCacheKey 承担（预分配不进池 key，两者各自场景互不依赖）。

    ★ 组合合法性构造时校验，非法抛 ArgumentException。

    FileSystemOptions

    options 家族基类（medium-protocol-and-parity-design §6）——名字回收自 G12 删除的遗留 God-options。

    ★ 准入标准 = "同词同义且全介质成立"；v1 三成员——Access（空间访问三态，一个枚举三个平面）/ Label（New = 设置 / Open = 校验——时刻语义见 §2.5）/ QuotaBytes（空间根上限，-1 哨兵）。

    ★ 不满足准入标准的参数宁可重复出现在子类，不上收（防 God-options 回潮）。

    LocalSpec

    local:// spec 构造器——With 方法集 = [SpecParam] 派生（TierSpec 属性面）。

    MemorySpec

    memory: spec 构造器——With 方法集 = [SpecParam] 派生（TierSpec 属性面）。

    NetworkSpec

    network:///s3 spec 构造器——With 方法集 = [SpecParam] 派生（TierSpec 属性面）。

    SpecSizeExtensions

    spec DSL 尺寸后缀人机工学（spec-typed-frontend-and-generator-design §4 P-b）—— 1.Giga() ≡ spec 字符串 quota=1G（1024 基；往返同义由 DSL 契约测试钉死）。

    Specs

    spec 构造 DSL（L2 编译期安全层）——非法参数×介质不可写出；ToString = spec 字符串。

    TierFs

    TierFs——spec 工厂（medium-protocol-and-parity-design §2.2）："打开一个存储镜像"的统一入口。

    ★ 两级注册表：顶层 = 四本性根（封闭——本类内路由）；二级 = network 协议表（开放注册）。

    ★ 工厂是薄壳：解析 spec → 委托各介质类型化入口（P2 各介质落位 New/Open 后重新对靶）。

    ★ 骨架纪律：spec 参数全量解析校验；介质尚未落地的参数**显式抛 NotSupportedException（带 阶段号）**——绝不静默忽略（静默忽略 = 配置写了没生效，比报错恶劣）。

    TierSpec

    spec 解析结果（medium-protocol-and-parity-design §2.1 方案甲）——构造协议的结构化形态。

    ★ scheme 头 = 本性四类（local/memory/virtual/network——封闭）；二级分类 = path 首段 （virtual 的 dev 设备载体 / network 的协议名——开放注册键）。

    ★ local 路径域四形态：POSIX 绝对（local:///var/…）/ Windows 盘符（\ 与 / 都收，解析时归一 /）/ UNC（local://server/share）/ 相对（local:rel—— CWD 固化由工厂负责，解析层保持原样）。

    ★ 快捷档：local ≡ local: = CWD 根；memory ≡ memory: = 缺省私有卷； virtual/network 无裸形态（fail-fast——没有默认载体与默认端点）。

    ★ ToString() 输出规范形——往返稳定：Parse(Parse(s).ToString()).ToString() 恒等（设计 §7.3 往返测试的锚点）。

    VirtualSpec

    virtual:// spec 构造器——With 方法集 = [SpecParam] 派生（TierSpec 属性面）。

    VolumeInfo

    卷几何信息——两个独立探测、职责不同的对齐基准（可不同：512B 逻辑扇区+4K 簇；NTFS 4K 扇区+64K 簇）。

    ★ SectorSize = 物理扇区——DIO 读写对齐基准（Win DIO 句柄的 RequiredAlignment 升为 max(sector, 内存页)）。

    ★ AllocationUnit = fs 簇/分配单元——空间操作（PunchHole/Collapse/Insert）对齐基准；mem = PageSize。

    Structs

    FsEntry

    根空间统一枚举条目（filesystem-root-space-design §3.3）——三族枚举（Files/Directories/Entries）共用。

    ★ 轻量：不含元数据（S3 ListObjectsV2 不返回用户元数据——枚举携带 = 逐键 HeadObject，不可接受）； 完整信息（含 ≤2K 元数据）见 FsEntryInfo（IFileSystem.Stat 专用）。

    ★ Name = 相对所枚举目录的路径（recursive=true 时多组件 "sub/f"）； Length 文件=字节数、目录恒 0；LastWriteTime 文件三介质必有，S3 目录不可得 = MinValue； CreationTime 可空 = 介质不可得（NTFS ✓ / Linux 视 statx / S3 恒 null）。

    FsEntryInfo

    单条目完整信息（IFileSystem.Stat 专用）——FsEntry 全字段 + 用户元数据（≤2K）。

    Interfaces

    IFileHandle

    单个文件的访问与操作——Core/IO 数据平面（fd 模型 ∪ overlapped 模型，D7）。

    一个 IFileHandle 实例对应一个文件的一种打开语义（Access × Mode × Sharing × Hints）。

    ★ 磁盘实现：SafeFileHandle + RandomAccess（内含 DIO 对齐校验与逐句柄探测）。

    ★ 内存实现：槽代际寻址（open 时解析一次，热路径零字典开销）。

    ★ 位置语义并集：Write/Read(offset) 保持 pwrite/pread 无状态铁律（不读不推进游标）； 句柄同时内建生命周期游标（open 初始化、Append(ReadOnlySpan<byte>) 原子预留推进、Seek(long, SeekOrigin) 移动）。

    IFileSystem

    根空间管理器——命名空间平面（路径/目录/枚举/元数据）与数据平面 IFileHandle 拆分 （OS 模型：pread 属 fd，rename/readdir 属命名空间）。

    ★ 模型（filesystem-root-space-design）：一个 IFileSystem = 整个存储系统的根空间—— 内部全相对路径的层级命名空间（'/' 唯一分隔符，组件化校验见 PathValidator.ValidateRelative）。 目标布局 {root}/{数据结构}/{引擎}/{段文件、整理目录}；上层经本表面完成全部命名空间管理， 零 BCL File/Directory 依赖（三介质平权：Disk/Mem/Remote 实现同一接口，能力位表达差异）。

    ★ 创建/句柄解耦：CreateFile(string, long, ReadOnlyMemory<byte>) 提前创建（预分配+元数据，建段协议移出热路径）； Open(string, FileOpenOptions) 保留即建即用模式族（FileMode 语义）。

    ★ FileExtra 平面（§3.6）：一份不透明附加数据 ≤MaxFileExtraBytes（创建即写/句柄四成员 2KB 上限）；Stat(string) 全量读；枚举条目 FsEntry 轻量不携带（S3 列举不返回 用户元数据——携带 = 逐键 Head，不可接受）。

    ★ 枚举契约（对齐 POSIX readdir）：不保证原子快照（枚举期间增删可见性未定义）、不保证顺序 （消费者自行排序）；模式匹配 = */? 通配（BCL MatchType.Simple，Ordinal）， 匹配目标为条目最终组件名；单参重载的 string 实参是 pattern（根范围），子目录枚举须双参。

    ★ Dispose 契约（方向差异必须显式认知）：磁盘 = 仅释放 fs 自持资源（卷锁违约释放、探测缓存）， 不关闭消费者持有的句柄（OS 句柄归消费者），已开句柄继续有效；mem 特例 = 销毁卷（"拔盘"）—— 全部槽归还池（含 Detached），此后其任何句柄操作抛 ObjectDisposedException。

    IMappedSection

    内存映射视图——生命周期独立于父句柄（Map 私有化底层引用：mem=槽引用计数 / disk=OS 句柄复刻）。

    ★ 铁律：必须 Dispose（其持有独立 OS 句柄/引用，不 Dispose = fd/引用泄漏）。

    ★ Dispose 后访问 View 抛 ObjectDisposedException（不返回悬垂 Memory）。

    ★ mem Sparse 模式写穿透契约：视图写在 Flush/Dispose 时写回文件（可见时点=Flush/Dispose，非实时）。

    ITierProtocolBuilder

    network 协议构建器（二级注册表的开放轴）——第三方 IObjectStore 实现注册 TierFs.RegisterProtocol("cos", builder) 即接入完整远程栈（扩展永不进 scheme 顶层）。

    Enums

    AccessMode

    访问三态（medium-protocol-and-parity-design §2.5/§5.2）——一个三值概念，三个平面： 空间（FileSystemOptions.Access）、文件（FileOpenOptions.Access）、映射（Map API）。

    ★ 空间平面即总上包络：句柄/映射构造期校验 ⊑ fs.Access，越包络即抛、不构造。

    ★ 本枚举为目标词汇先行落位；P3 完成 AccessMode 改名与 AccessMode 并入。

    FileAdvise

    访问提示（posix_fadvise 族语义）——告诉内核接下来的访问模式，供预取/回收决策。

    FileLockMode

    字节范围锁模式（fd 级协调原语，与卷锁分层）。

    FileOpenHints

    打开提示轴——缓存策略与访问模式提示（正交可叠加）。

    ★ NoBuffering 与 WriteThrough 可叠加（DIO + 写透）。

    FileOpenMode

    打开模式轴——文件存在性处置（BCL FileMode 对应）。

    ★ Append 仅控制句柄游标初始位置（EOF），不施加强制追加—— 与 BCL FileMode.Append / POSIX O_APPEND 均不同（后者已裁决不在本层）；多写者顺序追加用句柄 Append()。

    FileSharing

    打开共享轴——同文件并发打开约束（BCL FileShare 对应）。

    ★ POSIX 无原生对应，映射为 advisory 锁语义（平台差异文档化）。

    ★ 保护边界（advisory 本质）：仅约束同进程内经同一 fs 实例打开的句柄—— 外部进程 / 绕过本层的原生 IO 不受保护；跨进程互斥用卷锁（IFileSystem.AcquireExclusive）。

    FileSystemCapabilities

    文件系统能力协商位——介质异构的显式表达（一次性探测，消费者主动避免依赖回退）。

    ★ 契约：每个能力位对应的操作在未置位的实现上有文档化回退 （xattr→no-op、PunchHole→memset）或抛 Unsupported（无回退族，如 CollapseRange）。

    ★ DirectIO 是 fs/卷级静态能力（构造时探测）；句柄实际探测结果由 UnbufferedSupport 报告——两层互补，不可互相取代。

    FsEntryType

    条目类型（根空间统一条目 FsEntry 的判别）。

    IOError

    统一跨平台文件 IO 错误码——Core/IO 的底层统一错误分类（替代原生 Win32 HResult / errno 的碎片化处理）。

    ★ 值兼容 Runtime.Storage 旧 IOError（前 9 个成员序号一致），仅追加新成员； 适配迁移期两套并存（本枚举属家族 A，旧枚举随旧目录消亡）。

    MaintenanceScope

    维护门闩的作用范围（EnterMaintenance(string, MaintenanceScope, CancellationToken) 的 scope 参数）。

    StorageNature

    介质本性（medium-protocol-and-parity-design §1.5/§2.1）——spec 协议头的值域，四类封闭（平权完备族）。

    ★ 三层一套词汇：文档标准术语 = spec 协议头 = VolumeInfo.Nature 观测值。

    ★ 二级分类在 path 首段（virtual 的 dev 载体 / network 的协议名——开放注册）， 本枚举只承载封闭的顶层；扩展永不进顶层。

    ★ 遗留 FileSystemType 枚举的分类学由此继承（G12——形态退场，概念留任）。

    TierFsVerb

    工厂动词（medium-protocol-and-parity-design §2.3）——New = 创建空镜像并打开（已存在即抛）；Open = 打开既有（不存在即抛）；OpenOrCreate = 懒初始化糖（bind-any——两态显式表达）。
