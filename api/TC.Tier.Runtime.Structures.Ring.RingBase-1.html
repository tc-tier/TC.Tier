RingBase 寻址 partial——热路径 TryAllocate/Seal/GetPhysicalAddress/GetSpan/GetInfo。

★ FASTER hybrid log 地址模型（照 AllocatorBase，仅 long→LogicalAddress + 引擎 API）：

- 地址单调递增，永远向前；不回退（不需要 ReclaimTail，那是 Log 变长页才用的）。

- 内存固定 PageCount 个 native 槽，slot = pageSeq & PageCountMask 循环复用。

- 写满一圈淘汰旧页（head 推进 FreePage），tail 继续 append（地址继续增长）。

★ 引擎地址空间提供 100% 确定的地址。Ring 基于 _dataStart + GetDistance 做 100% 正确寻址。

★ _dataStart 构造时 Allocate 确定（GetDistance 锚点）。pageSeq = GetDistance(_dataStart, addr) / PageSize。

★ 地址运算只用 CalculationAddress/GetDistance（§8 铁律，不碰 Offset 算术）。

Abort(long)

★ Abort（2PC 回滚，D2 决策落地）：TruncateSuffix 回退到上一已确认提交边界，丢弃本轮悬干数据。

回退点 = TC.Tier.Runtime.Structures.Ring.RingBase`1._txRollbackTail（ConfirmCommitted 推进的提交尾，随 meta 持久化为 CommittedTailAddress——跨崩溃的恢复裁决同一路）。⚠️ 窗口契约：上一提交点之后的全部写入 必须都属于被回滚的事务（标准 2PC WAL 契约——TransactionLog 协议天然满足； 混入非事务写会被一并回退）。

守卫矩阵：seq ≤ LastCommittedSeq（已提交）→ no-op；seq ≠ LastPreparedSeq（陈旧 Abort）→ 仅复位记账；无既有提交边界（Empty，如首事务）/ 无悬干数据 → 仅复位记账。

回退后 WriteMeta 持久化（窗口关 + seq 复位 + 回退水位）；溢出引擎的悬干值不回收 （无引用字节，无害残留）。

⚠️ 调用契约：与并发 Write 串行（事务终态点调用，TransactionLog 协议天然满足）； 回退点不可落入已驱逐区（TruncateSuffix fail-fast 守卫）。

Remarks

★ STORAGE-007 设计契约（中间层 epoch 责任划分）： 本方法（及 GetValue/GetRecord/GetRecords/TryGetKey/TryGetValue）不内部持 _epoch—— 刻意为高性能中间层 API。epoch 保护责任在调用方：

        <ul><li>上层（Index/RecordStore）若已注入共享 epoch（RingBase 构造 epoch 参数，RingBase.cs:127）并
          在其 Resume/Suspend 上下文内调用本方法，则 native 页在读取期间不会被驱逐（drain 等 epoch 退出）。</li><li>裸调用方（无 epoch 保护）需自行保证：addr 所在页在读期间不会被自动驱逐（如 mutable 区、
          或显式持 Ring._epoch：调用方线程 _epoch.Resume() ... 读 ... _epoch.Suspend()）。</li></ul>

        在内部持 epoch 会与上层注入的 epoch 重复 Resume/Suspend（多余开销）且无法保护返回的 span
        （方法返回即 Suspend，调用方持 span 期间仍可能被驱逐）——故采用中间层 NoEpoch 契约，
        由上层统一管理 epoch 生命周期。参见 FASTER ClientSession 模式。

Prepare(long)

★ Prepare（事务准备）：落盘数据 + meta。

数据 flush 到 TailAddress，meta 落盘（"悬干"状态——崩溃在此后 ConfirmCommitted 前恢复时丢弃）。

★★ meta 策略分路径（fsync 次数优化）：

- Transport 回落 MetaHost（宿主流嵌入，未注入传输）：WriteMeta 先（Commit 写页池纯内存， 记 dataTail 水位）→ FlushUntil 末尾。meta record 随数据同页 flush 落盘（原子），1 次 fsync。

- Managed/Transport(注入传输)/Disabled：FlushUntil 先 → WriteMeta。Managed meta 在独立文件， WriteMeta 必须在 FlushUntil 之后才能记真实的 FlushedUntilAddress（否则崩溃在 Commit 后 FlushUntil 前， meta 说刷到 X 但数据没真刷到，恢复丢数据），2 次 fsync。

TruncateSuffix(LogicalAddress)

★ 尾截断（D2 决策——放松"地址单调不回退"铁律的唯一异常路径）：回退尾水位到 address， 物理销毁 [address, TailAddress) 区间（引擎 ReclaimTail），回退内存水位/页池/冷缓存。

调用方：Abort（2PC 回滚悬干数据）。独立公开面供 Raft-leader 式显式回退场景使用。

★ 回退四件套（顺序敏感）：

1. 物理回收：engine.ReclaimTail（整段删除 + 段内打洞，字节级销毁不可恢复）；

2. 内存水位条件回退：Flushed/ReadOnly/SafeReadOnly/Tail 各自独立判断 current > target 才回退（盲赋会把低于目标的字段前推——多字段回退铁律）；

3. 页池清零：[address, 旧尾] 的 native 页字节清零（含半页起点 + 整页）—— 防回退区陈旧字节被后续热路径读成"有效 record"；

4. 冷缓存失效：回退区内页的缓存条目逐页 Remove——防冷读路径供旧字节。

⚠️ 守卫：address 不得落入已驱逐区（< SafeHeadAddress）——已驱逐页 native 内存已归还， 回退进该区意味着事务窗口横跨大规模非事务流量（协议违例），fail-fast 不静默损坏水位格。

⚠️ 调用契约：与并发 Write 串行（事务终态点调用；TransactionLog 协议天然满足）。 Head/SafeHead 不回退（已驱逐物理页不可复活）；若 Head 暂超前新尾，下次页环绕自愈 （读路由按 FlushedUntil，Head 只影响背压与驱逐）。
