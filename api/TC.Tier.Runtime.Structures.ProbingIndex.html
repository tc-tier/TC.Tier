    ProbingIndexBase<TKey>

    探测族基类（族 B：HashIndex）——条目 = 地址 + tag（不物化 key），判等经 IKeyResolver<TKey> 回读。

    ★ 族器官（设计稿 §3.2，从旧 IndexBase 收编）：ComputeTag/ComputeHash（hash 路由）+ CasSlot（128bit 桶并发）+ GrowIndex（resize 语义）。KeyResolver 构造期必注入非空——判等闭环硬依赖显性化（废 null 断言）。 KeyResolver 同时是恢复数据面：恢复核心拉 ScanAsync 流自填桶（设计稿 §4，索引=派生数据、真相源在 record 流）。

    ★ 自建主存储（设计稿 V2/index-persistence-evolution-design.md，机制在 ProbingIndexBase.Persistence.cs）： 基类=机制容器（后台 dump 编排/版本链 N 版轮替/帧走链恢复载入/策略触发），子类只实现格式布局 （几何 + 桶区/溢出池逐槽拷贝 + 物化——铁律 10，对齐 LogBase/RingBase/MirrorBase）。 持久化是结构核心能力（可关闭 PersistenceKind=None），镜像通道注入面已退役。

    ★ 不持有比较族器官（节点引擎读写）；无有序遍历（CreateScanCursor 是比较族能力）。

    ProbingIndexFooterCodec

    ProbingIndexFormat

    索引结构主存储帧格式——两族索引（探测/比较）共用的三段式帧格式 （设计稿 V2/index-persistence-evolution-design.md）。

    ★ 自校验三段式（段表同款理由——写入的是外部存储就不完全相信，只认自己的写入格式）：

    • 头（先行校验，快速失败）：magic/version/flags/kind + 体长——不符立即判无效，不读体；
    • 体（自定界）：结构内容由族自己的几何块推出边界（Hash=桶区/溢出池；BTree/SkipList=32B 几何，节点在引擎内）；
    • 尾（总验收）：footerMagic + 水位 W + CRC64（覆盖头+体+尾前缀）——有效性最终裁决。

    ★ 帧格式知识归 codec（IProbingIndexCodec 实现——子类=格式定义者）， 本类型只承载结构定义与共享常量；源生成器（[BinaryLayout]）生成 ProbingIndexHeaderCodec/ProbingIndexFooterCodec。

    ProbingIndexRecoveryHints

    探测族恢复 hints——重放窗口 [Begin, End)（设计稿 §4 两段式：组合层锚点触发 + index 自建）。

    ★ 组合层职责：恢复 Ring 后从 opaque 取锚点 W（无锚点/损坏 → W = Ring BeginAddress）， 连同 Ring 尾一起经 Initialize(hints) 注入——结构层水位正位通道。

    ★ 默认（无窗口）= 空结构首开，不重放；降级全量重建不是第二条路——W=Begin 走同一条 ScanAsync 路径。

    Interfaces

    IProbingIndexCodec

    ProbingIndex 主存储持久化格式契约（基接口——将来 BTree 标准化对齐时接入）。

    ★ 命名律：dump/checkpoint 是内部机制词不进类型名——codec 按结构名命名。

    ★ 契约律（对齐 ILogCodec）： 基类只管机制（帧走链/CRC 总验收/体长定界），格式知识（magic/version/kind/字段布局） 全在实现侧——接口只传机制需要的原始值，不暴露任何具体格式类型。
