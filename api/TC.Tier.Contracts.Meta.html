    IMetaPolicy<THeader, TPayload>

    Meta 策略统一接口——结构化元数据的持久化契约（独立能力，不限使用方）。

    ★ 统一布局：[Header 纯规范][Payload 结构化水位 + opaque 扩展][Footer Crc32C 4B]。 Header 只放规范字段（Magic/Version/Flags/PayloadLength/PaddingLength），水位一律走 Payload； opaque 是写在结构化水位之后的原始扩展字节，长度由 Header.PayloadLength 倒推。

    ★ 契约（所有实现必须一致）：

    • 未 Load 的读返回空——ReadHeader/ReadMetaPayload 返回 null、 ReadPayload 返回 Empty（Commit 成功后视为已 Load，同实例可读）；
    • 重新 Load 全量重置缓存——上一轮的 header/payload/opaque 不残留；
    • Load 返回 false 的三种情况等价：空/无数据/校验失败（Magic、版本、CRC、长度界）， 不区分原因；
    • Dispose 幂等，重复调用不抛。

    IMetaTransport

    Meta 传输契约——策略与存储介质之间的唯一通道：写一个完整 meta block / 读回最后一条。

    ★ 实现决定介质与放置策略（单槽覆盖 / 追加到自身存储流后倒扫 / 远程服务……）， 策略不关心；块的格式与 CRC 完全由策略负责（[Header][Payload][Footer Crc32C]）， 传输只搬字节——实现不需要理解块内容，也不承担完整性校验。

    契约：

    • 读写统一 Span/Memory 视图，零中间拷贝——WriteBlock 收 ReadOnlySpan<T>（byte），ReadLastBlock 回 ReadOnlySpan<T>；
    • 空 = 无数据——ReadLastBlock 返回 IsEmpty （异步版返回空 ReadOnlyMemory<T>）即"从未写入"，不用 null；
    • 视图生命周期——返回的 Span/Memory 有效至本传输的下一次调用 （实现以字段持有底层缓冲，不转移所有权）；调用方需要留存必须立即拷贝；
    • WriteBlock 写入的块即成为本传输的"最后一条"（覆盖或追加由实现决定， 语义上 last-write-wins）；同步/异步成员语义对等。
