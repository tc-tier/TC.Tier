    Class SessionManager

    ★ Session 管理器——组合域统一协调协议层（session-manager-design.md v2，Runtime/Transactions 收官件）。

    每组合域一个；读写检查点三 op 的唯一进出：写=staged 物化委托经单飞提交管线 （纯内存序+排空批合并，FIFO 全序）；检查点=管线内串行回合；读=会话 scope/地址直达（协议面另件）。

    ★ 零自有存储、零持久化决策（v2 决策）：持久化真源=参与者各自 meta 水位 （2PC 六件套本就持久），时机归参与者自身策略；悬挂裁决按域声明（默认 forward-commit 前推）。

    线程安全（管线/计数/通道）；会话（TierSession）单线程使用契约。

    OnInitializeComplete()

    ★ Initialize 第二阶段（[后]）钩子——仅在本实例恢复成功完成后调用。

            <p>★ 不变量：Complete / Ready / 恢复完成 三者同义。每层都用同一 <xref href="TC.Tier.Core.Shared.LifecycleBase%601" data-throw-if-not-resolved="false"></xref>，
          故任意嵌套层此不变量都成立——父层在此钩子里可安全读"本层恢复产物"。</p>
        <p>★ 执行线程：有恢复时在后台 LongRunning task 内（串行接在 <code>await RecoverAsync</code> 之后）；
          无恢复（<xref href="TC.Tier.Core.Shared.LifecycleBase%601.CreateRecovery" data-throw-if-not-resolved="false"></xref> 返回 null）时在调用线程同步执行。</p>
        <p>★ 异常策略：恢复已 MarkReady、实例可用——钩子内抛异常只 log，不 fault 主 task。</p>
        <p>★ 需配 <xref href="TC.Tier.Core.Shared.BackgroundWorkerLoop" data-throw-if-not-resolved="false"></xref> 的子类：在 <xref href="TC.Tier.Core.Shared.LifecycleBase%601.OnInitializeBegin" data-throw-if-not-resolved="false"></xref> 或本钩子里调
          <xref href="TC.Tier.Core.Shared.LifecycleBase%601.ConfigureBackgroundWorker(TC.Tier.Core.Shared.BackgroundWorkerLoop)" data-throw-if-not-resolved="false"></xref> 均可——worker.Start 在本钩子<b>之后</b>跑（等恢复完成 + 装配就绪）。</p>
