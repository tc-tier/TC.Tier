LogMetaHeader

LogMeta header（12B 纯规范字段，对齐 RingMetaHeader 范式）。

★ 三段式：[LogMetaHeader 12B][LogMetaPayload 64B(+预留扩展)][Crc32Footer 4B]。

★ 水位（BeginAddress/TailAddress/CommittedOffset）不在 Header——作为 Payload 区首部（LogMetaPayload）。

★ FlushedUntilAddress 删除——新模型用 engine.Flush，引擎 CommittedTail 是 pwrite 水位不等于已 fsync。

★ [BinaryLayout] → 源生成器生成 LogMetaHeaderCodec.Write/Read。

参见 base.md §3 D。

LogMetaPayload

LogMeta Payload 区结构化首部（4 LogicalAddress = 64B + LastCommittedSeq 8B + LastPreparedSeq 8B = 80B）——水位数据。

★ [BinaryLayout] → 源生成器生成 LogMetaPayloadCodec.Write/Read。

★ 地址全部 LogicalAddress（承自 spec 27 第一不变量，大小绝不参与）。

★ PreparedTailAddress（2PC Abort 回退点）：Prepare 时刻的 pre-prepare 尾快照—— 本轮事务窗口数据的起点。Abort/恢复裁决据此 TruncateSuffix 回退；Empty = 无待回滚窗口。

参见 base.md §3 D。

Interfaces

ICommitPolicy

提交策略接口——EntryLog group 提交引擎按策略判定"何时"触发提交（不决定"怎么"提交）。

★ 策略只决定"何时"，提交执行链（FlushUntilAsync + MetaPolicy.Commit + 推进 CommittedOffset）由 EntryLog 内部闭环。 参见 EntryLog.md §3.5。

内置策略：

- TC.Tier.Runtime.Structures.Log.GroupCommitPolicy：三维度阈值兜底（数据量/时间/记录数任一满足）

- Synchronous：恒 true（每次 Append 立即提交，单条强制）

- External：恒 false（不自动提交，靠手动 CommitAsync 或 2PC）

ILogCodec

Log entry 头尾编解码接口——注入 LogBase，消除虚分发。

基类只管传输（页管理/tail/flush/epoch），codec 管格式（header/footer/CRC）。

ILogCursor

Log 扫描游标接口——继承 Shared IStructureScanCursor 统一骨架，扩展 Log 专属 entry 几何成员。

★ 单接口，同步/异步共存（MoveNext() 同步 + MoveNextAsync(CancellationToken) 异步）。

★ 去泛型：CurrentEntryType(TEntryType) → CurrentIsMeta(bool)。Log 只区分"数据 vs meta"两种。
