    Class EntryLog

    EntryLog — 通用 entry 顺序日志实现类（WAL 是其典型用途，非唯一用途）。

    ★ EntryLog.md：通用 per-entry [16B EntryCodec header][payload+4B对齐] 纯追加顺序日志。

    ★ 提交模型（两层，职责分离）：

    1. 底层页提交契约（恒成立，不可配置）：Append 跨页 → FlushPage 数据落盘 → OnPageFlushed(LogicalAddress) 同步执行 commit 链（meta.Commit + 推进 CommittedOffset）。 这是页模式的本质保证——前一页换出时即持久化，无需任何策略注入。最坏情况：写满一页才提交。

    2. 可选提前提交（注入式优化，降延迟）：ICommitPolicy 在页未满时提前触发提交。 注入 null（默认）= 仅依赖底层页契约；注入 TC.Tier.Runtime.Structures.Log.GroupCommitPolicy = 三维度提前提交。

    ★ 上述两层取代旧的"fire-and-forget 后台循环 + Append 内 spawn 提交"模型——后者线程池饥饿即系统挂， 且错误被静默吞。新模型提交都在写线程同步完成，无并发、错误冒泡。

    OnAppended(LogicalAddress, int, bool)

    每次 Append/AppendAsync/AppendBatch 后调用：累计未提交量，按策略判定是否提前提交。

    ★ 默认 GroupCommitPolicy（从 settings 三维度阈值构造），三维度任一满足即触发。

    ★ P0 修复：提前提交必须先 flush（FlushUntil）把内存页数据落盘，再推进 CommittedOffset——

    保证 §7 不变量 CommittedOffset ≤ FlushedUntil（已 commit 必已落盘）。

    旧实现直接 CommitCore(TailAddress) 跳过 flush，TailAddress 可能指向仍在 _pageBuf 内存的 entry，

    导致 _committedOffset 超前于真实落盘字节，崩溃丢失已 commit 数据。

    OnPageFlushed(LogicalAddress)

    ★ 底层页提交契约（恒成立）：每次页 flush 落盘后同步 commit 到 flushedUntil。

    由基类 FlushPage（跨页 Append / Flush / Dispose）在 IO 完成后调用。此方法在写线程同步执行， 无并发、无 fire-and-forget、错误冒泡到 LastCommitError。

    这是页模式的本质保证——前一页换出即持久化（数据 + meta + CommittedOffset 推进）。 不依赖任何注入策略，删除 ICommitPolicy 此保证依然成立。
