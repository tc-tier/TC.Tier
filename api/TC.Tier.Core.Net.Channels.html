Namespace TC.Tier.Core.Net.Channels

Classes

FeedChunkReq

按 offset 取块请求（同 offset 重试幂等——续传语义基石）。

FeedChunkResp

取块应答。

QosManager

QoS 管理器（二期-E4 NETGAP-032——每协议/每来源配额与限流）： 两级令牌桶——域级聚合 + 域内按来源（租户=来源节点语义）；TryAdmit 双级全过才准入。 策略运行期可变（重复 Set = 重置桶）；未设置 = 不限流（既有语义）。

RequestBatch

协议级批量/管道（二期-E5 NETGAP-033）：把 N 个单项请求封装为一个请求帧 （一次往返摊薄 per-request 开销），应答同样批量回程（逐项 status + 载荷）。

★ 信封（自描述、帧头不动）：

请求  [count 4B][×N: len 4B + bytes]
应答  [count 4B][×N: status 1B + len 4B + bytes]   status: 0=ok, 1=error

★ 管道：批量请求之间天然并发（传输 CorrId 独立配对）——同链多批在途即管道。

★ 约束：批量域 handler 须同步应答（快进快出——deferred 应答不兼容批量聚合）； 单项上限/总量遵循帧 16MB 上界（Encode 超限抛）。

RequestBatchClient

批量客户端助手（管道 = 多批并发在途——传输 CorrId 独立配对）。

RequestBatchHandler

批量服务端适配器（二期-E5）：包装单项 handler——解码批量请求 → 逐项调用 → 聚合批量应答。 逐项异常 = 该项 Error 标记（其余项不受影响）。批量域 handler 须同步应答。

RequestDegradeException

满载降级异常（二期-D5——Degrade 专用失败面）： 语义 = "系统满载已降级拒绝"，区别于 fail-fast 的"调用方失控"——产品据此 fallback/限流告警。

RequestOptions

请求回调发送选项（spec-12 §5.2——per-call 覆盖传输缺省）。

ResumableFeedClient

可恢复流客户端（二期-E2——拉取式消费）：从 startOffset 起按 offset 顺序拉取，每次成功才 前进——断链/超时以同一 offset 重试即续传（不丢不重）；HasChunk=false+HasMore=false = 完成。

ResumableFeedMessage

可恢复流消息族（二期-E2 NETGAP-028——offset/resume 令牌原语）： 拉取式按 offset 取块——断线/超时以同一 offset 重试即续传（按 offset 幂等，天然不丢不重）。

★ 线格式（生成物：[Tag 1B][字段声明序]，小端）：

FeedChunkReq   [Tag][FeedId 16B][Offset 8B]
FeedChunkResp  [Tag][Offset 8B][HasChunk 1B][HasMore 1B][Len 4B][Data]
ResumableFeedMessageCodec

ResumableFeedMessage 消息族线编码——[WireMessage] 派生。

ResumableFeedServer

可恢复流服务端（二期-E2）：有界保留窗 + 单调 offset 分配—— Append(ReadOnlyMemory<byte>) 产出块 offset，OnRequest(NodeId, ReadOnlyMemory<byte>, IReplyContext) 按 offset 供块； 保留窗外缺口 = HasChunk=false + HasMore=true（客户端稍后重试），越过尾部 = 完成。

RetryPolicy

请求回调投递语义·at-least-once 档（spec-12 §5.2——重传/确认是请求回调的附加能力， 可靠 = 显式选择）：同 CorrId 重发 + 应答端去重窗口（识别已服务请求 → 缓存响应重放， 不重复执行——handler 幂等是使用方约定，跨重启窗口不持久 §8.4）。

★ 缺省不配置 = at-most-once（单发 + 超时）；数据报形态永不隐式重传。

TokenBucket

令牌桶限流器（二期-E4 NETGAP-032——QoS 基元）：桶容量 = burst（突发额度）， 按 perSecond 匀速回填（惰性结算——按需重算，无后台线程）。线程安全。

Interfaces

IDatagramHandler

协议域数据报处理器（spec-12 §5.1——按协议 ID 分发后的入站回调；形态面 API）。

IProtocol

协议域面（spec-12 §3.5/§5——端点的多路复用子系统：协议域注册分流 + 数据报/请求回调/流式 三形态收发；全部成员以 protocolId 为参数）。

★ 数据报语义（尽力送达，§5.1）：对端未连/未注册协议/注入丢弃 = 静默丢弃——协议域自愈； handler 快进快出（回调异常不外泄、不杀链路）。

★ 注册面（§3.5 分流）：公开口只放行注册区 0x60-0xAF——使用方自管号码； 内部核心区经程序集内 internal 挂载口（TC.Tier.Core.Net.Channels.ICoreProtocolPort——机制面专用）。 bearer 声明承载偏好（介质不支持时回落/直派——尽力语义不变）。

★ 请求回调（§5.2）：单请求 → 关联应答 → 超时；CorrId 传输生成；目标未连 = NetIOException（调用方有应答期待，不静默浪费超时窗）；投递语义缺省 at-most-once，重传/确认 = 显式选择（RetryPolicy——at-least-once）。

★ 流式会话（§5.3）：可靠有序 + 背压；GB 级 O(单帧) 不驻留；未注册 acceptor 的 协议域 = 拒绝开流。

IProtocolTransport

节点端点完整面（spec-12 §5 形态面消费面——机制/装配/使用方实际持有的类型）： 连接面（ITransport：身份/生命周期/对端观测/注入）× 协议域面（IProtocol：注册分流 + 三形态收发）合一。

★ 介质无关消费面（§12 同构门的抽象基础）：同一机制/产品代码不改一行换介质 （InProcess = 同构基准/语义参考实现）。

IReplyContext

应答上下文（spec-12 §5.2）——回程路由知识在介质（TCP 链路回写 / InProcess 定向投递）， handler 只见 ReplyAsync(ReadOnlyMemory<byte>, CancellationToken)；CorrelationId 由传输内核生成（机制消息族不携带）。

IRequestHandler

请求回调接收面（spec-12 §5.2——形态面对高层的 API 契约）：单请求 → 关联应答 → 超时。

★ 回调契约同数据报 IDatagramHandler：快进快出（重活自排队）、 异常不外泄不致命；不回复 = 对端超时（ReplyAsync 零次调用合法）。

★ 幂等约定：at-least-once（RetryPolicy）下同 CorrId 请求可能重发——传输端 去重窗口缓存重放应答不重复执行；跨重启窗口清空（§8.4）——handler 幂等是使用方约定。

IStreamAcceptor

流式会话接受面（spec-12 §5.3——RegisterStreamAcceptor(protocol, acceptor) 的回调契约）。 未注册 acceptor 的协议域 = 拒绝开流（发起端 OpenStreamAsync 抛 NetIOException）。

ITransport

传输连接面（spec-12 §4/§7——介质无关的连接契约）：节点身份/生命周期/对端可达性观测/故障注入。

★ 与 IProtocol（协议域面——注册分流+三形态收发）正交；介质实现两者 （经 IProtocolTransport 合一），消费方按需持半边或整面。

★ 介质语义对齐：对端可达 = TCP 握手完成 ∥ InProcess 节点注册；离线 = 链路断开 ∥ 注销。 注入面 Faults 常设（§9.2——延迟/分区/丢包/乱序，任一介质等价复跑）。

IWireStream

流式会话（spec-12 §5.3——可靠有序 + 背压；GB 级 O(单帧) 不驻留）：StreamOpen/Accept/ Data/End/Reset 帧族承载，会话号 1..254，不跨重连恢复（上层重开）。

★ 背压 = 写 await 传导：接收侧会话缓冲有界，满 → 介质读循环 await → 对端 socket 写 await → 本端 WriteAsync(ReadOnlyMemory<byte>, CancellationToken) await——整链传导。

★ 生命周期：写端正常收尾 CompleteAsync(CancellationToken)（End 帧——对端 ReadAllAsync(CancellationToken) 自然结束）；异常中止 = DisposeAsync() （Reset 帧——双方读写立即终止）。

DatagramBearer
