握手/Negotiate/Error 帧一律走管理通道——握手完成前/后它都是唯一不依赖会话状态的通道； 数据报/流式帧在握手完成前到达 = Error + 断连。

FrameCodec

帧成帧薄层（spec-12 §3.1——介质无关；布局读写由 [BinaryLayout] 生成的 FrameHeaderCodec 产出，本层只持帧语义：HeaderCrc 计算/校验、版本与长度上限判定、 载荷拷贝）。

★ 解码两段式服务流介质（TCP：读 16B → 验头 → 读 PayloadLen 字节 → 验载 → 交付）： TryReadHeader(ReadOnlySpan<byte>, out FrameHeader) → 切载荷 → VerifyPayload(in FrameHeader, ReadOnlySpan<byte>)；数据报介质 （InProcess/UDP）用 TryDecode(ReadOnlySpan<byte>, out FrameHeader, out ReadOnlySpan<byte>) 一步到位。

★ 拒绝语义（Try 返回 false，传输层据此 Error + 断连 + 计数）：头 CRC 不符 / 头版本 ≠1 / 载荷长度超上限 / 载荷字节数不足 / 载荷 CRC 不符。未知 Kind/ProtocolId 不在编解码层拒绝（向前兼容——丢弃+计数是传输层策略）。

★ CRC 一律 ComputeCrc32C(ReadOnlySpan<byte>)（CRC32C 硬件加速）。

NegotiateCodec

Negotiate 帧薄层（spec-12 §3.2 0x1F——特性协商扩展帧；版本内新特性走此帧，不改既有帧格式）。 载荷 = [Tag 1B][Tag 数据]；Tag 0x01 = UDP 端点通告（§4.5 特性位 bit1）。

★ 载荷布局 [BinaryLayout] 声明（UdpEndpointV4/UdpEndpointV6， 地址 = Opaque4/Opaque16 不透明字节串嵌套件； [ValidEquals] 锁 Tag/Family 规范字段——Write(validate:true) 防御性补全）；本层只持 Tag 分发与 IPAddress 边界转换——零手写字节序、零偏移、零数组拼装。

★ 通告时序：三步握手完成（双方都收到 Final）后，协商出 bit1 的一侧各发一帧 （管理通道）——对端据其登记 UDP 发送端点。通告缺失 = 对端回落 TCP 承载（尽力送达）。

ProtocolIds

RequestCodec

请求回调帧薄层（spec-12 §5.2——Request 0x08 / Response 0x09，载荷 = [CorrId 8B][payload]）。

★ 布局知识在 CorrelationPrefix（[BinaryLayout] 声明式生成——零手写 字节序/偏移）；本层只做前缀拆装与载荷切片边界。

防御：载荷 < 前缀尺寸 = 违规帧（返回 false——丢弃 + 计数，不致命）。

SpanContextCodec

trace 上下文线格式（二期-I4 定案——请求载荷前缀形态）：

  • 上下文本体 = [TraceId 16B][SpanId 8B][Flags 1B]（25B 定长）；
  • 带前缀载荷 = [Marker 0x54][上下文 25B][业务载荷]（26B 头）。

★ 门控纪律：仅握手特性位 Trace 协商成功才加/剥 ——混版滚动升级下旧对端载荷零变化（N-1 兼容，H2 升级矩阵的组成纪律）。

★ 语义归 tracer：本层只做字节搬运——解释/续链由外部 tracer 的对称 CaptureContext/BeginSpan(parent) 承担。

CorrelationPrefix

请求回调载荷公共前缀（[CorrId 8B]——spec-12 §5.2；Request/Response 帧共享）： [CorrId 8B][payload]——payload 长度由帧头 PayloadLen 推导（无内部长度前缀）。

★ [BinaryLayout] 声明（生成 CorrelationPrefixCodec——读写零手写字节序）； CorrId 由传输内核生成（机制消息族不再各自携带关联字段——spec-12 §5.2）。

ErrorPayload

Error 帧载荷（spec-12 §3.2 0x7F——传输层错误报告：管理通道 + 管理协议域）。

★ [WireArray] 变长线编码（spec-12 §10 E1）：[Code 1B][Count 4B][Detail UTF-8 字节块] ——计数、位置、字节序全部由生成的 ErrorPayloadCodec 产出；空 Detail = Count 0。

收到 Error = 对端拒绝/违规告知 → 断连（拨号方走重连退避）；Detail 诊断文本由 TransportError 薄层做 UTF-8 边界转换与超长截断。

FrameHeader

帧头（spec-12 §3.1——16B 定长、全部小端、介质无关：TCP 流帧与 UDP 数据报同一套头）。

★ [BinaryLayout] 显式声明布局（spec-12 §10 声明即代码）——全部字段（含 HeaderCrc）的位置/读写/偏移常量由生成的 FrameHeaderCodec 产出； 本层零偏移知识，FrameCodec 薄层只持帧语义（CRC 计算与校验、版本与上限判定）。

★ 加字段 = 加一行 FieldOffsetAttribute 声明（TCSG001 锁 Size 与偏移和 一致）——手写偏移量在字段增删时整套漂移的形态不复存在。

偏移    宽度  字段
[0..4)  4B   PayloadLength   载荷长度（≤ 16MB）
[4]     1B   Kind            帧种类（）
[5]     1B   ChannelId       通道标识（）
[6]     1B   ProtocolId      协议域 ID（）
[7]     1B   Version         线协议头版本（=1；本 codec 只讲 v1）
[8..12) 4B   HeaderCrc       CRC32C（覆盖本字段之前的全部头字节——防半帧/错位；
                              值依赖已写出的头前缀，构造期 0 占位、由 FrameCodec 计算补写）
[12..16) 4B  PayloadCrc      CRC32C（覆盖载荷）

★ 头版本 1 的字段永不再解释——演进走版本协商 + 新 FrameKind（spec-12 §3.2）。
