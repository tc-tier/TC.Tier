    Class RemoteFileSystem

    远程文件系统——IFileSystem 第三介质桥（B3.3/B3.4）：注入的 IObjectStore 升格为文件语义（staging 写回层 / 延迟加载 / multipart 编排 / fencing 卷锁）。

    ★ 构造：New(IObjectStore, RemoteFileSystemOptions?, ILogger?) / Open(IObjectStore, RemoteFileSystemOptions?, ILogger?) / OpenOrCreate(IObjectStore, RemoteFileSystemOptions?, ILogger?)——store 注入 （S3ObjectStore / MemoryObjectStore / 任意实现），桥对厂商零知识。

    ★ 键模型：对象键 = {KeyPrefix}{path}（多引擎共桶隔离）；path 经 TC.Tier.Core.IO.Shared.PathValidator （三介质同一实现——越出前缀即 ArgumentException，不可能访问同桶其他前缀对象）。

    ★ Dispose 契约（磁盘方向）："离开目录"——Dispose 后 Open 抛 ObjectDisposedException； 已开句柄继续可用（staging 自持——远程数据在云端不在 fs 内存）；store 归调用方所有不代释放。

    ★ AcquireExclusive = 尽力型 fencing（lock 对象 + 条件 PUT；仅防意外双开，不构成正确性保证—— 时钟漂移可致提前抢锁、崩溃后保护真空 = 心跳超时窗口；引擎正确性由段表 lease 单写者协议承担）。

    EnterMaintenance(string, MaintenanceScope, CancellationToken)

    进入维护态（能力位 MaintenanceGate 门控；未置位实现抛 Unsupported）—— 采集/还原静默快照的通用前置（raw-medium-and-conversion-design §8）。

    ★ 语义：闭门 → 阻塞等待在途变异归零（ct 可取消；消费者业务在途收敛是消费者契约，§8.2） → 返回 IDisposable 租约（Dispose 即解除）。非重入：维护中二次 Enter 抛 FileIOException(UnderMaintenance)。

    ★ scope=WriteOperations：命名空间变更与句柄写族拒绝（读放行——备份档）； scope=AllOperations：读写全拒（完全隔离档）。 被拒操作抛 FileIOException(UnderMaintenance)——与能力位语义 Unsupported 分离，调用方可映射"维护中"提示。

    ★ Flush/FlushRoot 不拒（关闭协议的组成：进维护 → 收敛 → Flush 置 clean）。
