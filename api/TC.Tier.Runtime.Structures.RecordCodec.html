CRC 算/验统一工具——所有类型共用（unified-binary-layout.md §3）。

★ 规范字段（magic/version/flags/payloadLength/paddingLength）的读写已由源生成器生成的 XxxHeaderCodec.Write/Read 承担（偏移源自 [FieldOffset]，端序强制 LE）——本类不再管规范字段。

★ 本类只管 CRC：算法（CRC32C/CRC64）和位置（Header 末尾 / Footer 末尾）由 flags 决定。 调用方负责算 crcCoverEnd（= headerLen + payloadLen + paddingLen [+ footerMagicLen]）和 crcOffset。

VerifyCrc(ReadOnlySpan<byte>, ushort, int, int)

校验整条记录的 CRC（零拷贝主体：仅 CRC 字段位置喂入等长零字节，无整记录拷贝/无堆分配）。

★ CRC 字段位置在覆盖范围内时，须按 0 参与计算（与 FillCrc(Span<byte>, ushort, int, int) 清零后算一致）。 分三段：[0,crcOffset) + crcLen 个 0 字节 + [crcOffset+crcLen, crcCoverEnd)。

★ CRC 在末尾（footer）时 crcOffset==crcCoverEnd，单段算 [0,crcCoverEnd)，CRC 不在范围里。

★ 比"拷贝整条记录到临时缓冲再清零"省去 O(crcCoverEnd) 拷贝 + 堆分配；CRC32C 走硬件指令原位算。
