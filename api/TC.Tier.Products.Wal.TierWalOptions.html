Hints

★ IO hints——默认 NoBuffering（DIO）。

★ 依据（storage-engine-perf-baseline.md §3.5 写矩阵）：TierWal 页模型默认 4MB 页 → 页刷 = 大块顺序写，落在 DIO 甜区（写交叉点 ~256K；4M 块 DIO = 缓存写 4.3×，免双缓冲 拷贝 + 免内核 writeback 线程竞争）。mem 等不支持介质自动降级（UnbufferedSupport=Ignored， 零分支）。

★ 磁盘介质调优（tierwal.md §2 写矩阵实测）：HDD 上 DIO 单独是反模式（p99=178ms）， 须叠加 WriteThrough（DIO+WT p99=0.43ms，全介质最优）。 raft 磁盘部署建议：.WithHints(FileOpenHints.NoBuffering | FileOpenHints.WriteThrough)。 mem 介质 WriteThrough 无副作用（no-op）但会令引擎 Flush 短路——当前仅磁盘显式选。

★ 读侧权衡：DIO 直读比页缓存慢 1.6-3.6×——TierWal 复制/重放读经游标自管页缓存 （usePageCache）命中吸收，尾部热读不受影响。

public FileOpenHints Hints { get; }

WorkerScheduler

引擎 worker 调度器（共享注入形态，null = 缺省自建）。

★ 一个 TierWal = 主日志 + Managed meta + 镜像快照（+快照 meta）多个引擎：null = 各引擎 自建专用调度线程（2~4 条/引擎——多实例线程数与实例数线性绑定）；注入 = 全部引擎共用该实例 （所有权 Referenced——TierWal 释放不回收，生命周期归注入方），多实例线程数恒定。

嵌入式/多节点同进程（Multi-Raft、测试拓扑）注入 IsolatedTaskScheduler.Shared 或自建小容量实例——一组线程服务全部引擎。磁盘介质高频写场景慎用小容量（worker 排队 会拖慢组提交），2~4 线程起步按压测定。显式实例恒优先于 WorkerSchedulerOptions 配置形态（引擎构造：实例参数先于选项配置判定）。

public IsolatedTaskScheduler? WorkerScheduler { get; }

Property Value

IsolatedTaskScheduler
